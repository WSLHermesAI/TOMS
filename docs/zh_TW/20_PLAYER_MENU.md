# 20 — 玩家選單：一個按鈕包辦一切（規劃）

> English: [../20_PLAYER_MENU.md](../20_PLAYER_MENU.md)

**狀態：** **P1 已於 2026-10-10 完成**（§9）；P2、P3 和裝備強化（W26）尚未完成。Q11–Q15 已由擁有者於 2026-10-10 回答
（列在 [../progress_report/PROGRESS_REPORT.md](../progress_report/PROGRESS_REPORT.md)）。

行走畫面只保留 **一個按鈕** ≡。現在其他所有按鈕（背包、商店、全螢幕按鈕、原本的 ≡ 清單）都 **移進玩家選單**，
讓畫面上只剩地圖、數值和這個按鈕（§2）。

玩家選單共五個分頁：

1. **狀態：** 玩家的屬性和進度。
2. **裝備：** 更換武器和防具。
3. **道具：** 玩家擁有的東西，左邊是每列 3 個的格子；右邊是選中道具的資訊、價格和動作（使用／裝備／丟棄）。
4. **事件：** 玩家的任務和事件，排版和道具一樣：左邊清單，右邊是選中項目的詳細內容和下一步。
5. **系統：** 商店、功法、鍛造、村莊、存檔、設定、全螢幕、回到標題。

遊戲 UI 使用 RmlUi（[08_RMLUI.md](08_RMLUI.md)）；這個選單讀取的事件資料和規則在
[event_editor/06_EVENT_LOGIC.md](event_editor/06_EVENT_LOGIC.md) §7。

## 2. 一個按鈕：≡

**改變後的行走畫面：**

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 第 3 層 · 黃泉道                                                       [ ≡ ]•│
│ HP ███████████░░░ 82/150   ATK 20 DEF 7 LV 4   GOLD 45 EXP 37   Y1 B0 R0     │
│                                                                              │
│                              （地圖）                                         │
│                                                                              │
│ （方向盤，只在手機）                                                          │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **≡** 是行走畫面中唯一的按鈕，在右上角，大小適合拇指點。上面的小點 **•** 表示「裡面有新東西」：商店解鎖了、
  事件紀錄有變化、有功法點數可用、拿到新裝備。有新消息的分頁也有自己的小點；打開它就清除那一部分。
- 手機上的方向盤保留：它是移動，不是選單按鈕。
- 橫幅、章節卡和下方的劇情字幕保留；它們不是按鈕。

**打開方式：**

| 方式 | 打開 |
|---|---|
| ≡（點擊）、**Esc** | 選單，停在上次用的分頁（第一次：狀態） |
| **C** | 狀態 |
| **I** | 道具（和現在的背包鍵一樣） |
| **B** | 直接打開商店（和現在一樣），如果已解鎖 |
| 選單中：**Q** / **E** 或 **Tab**，或點分頁 | 切換分頁 |
| 選單中：**Esc**、✕ 或再按 ≡ | 關閉 |

- 只在行走階段可用：戰鬥、對話、商店和標題畫面中不行。
- **打開時遊戲暫停**，和現在所有視窗一樣（`modalActive()`）；遊走的怪物不會移動。
- **手機：** 面板佔滿畫面；分頁是上方的大按鈕；低於小螢幕門檻時（§8），裝備、道具、事件的左右分割改成先清單後詳細
  （點一下看詳細，◀ 返回）。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [ 狀態 ] [ 裝備 ] [ 道具 ] [ 事件 • ] [ 系統 ]                            ✕ │
├──────────────────────────────────────────────────────────────────────────────┤
│                           （選中分頁的內容）                                  │
└──────────────────────────────────────────────────────────────────────────────┘
```

**分割排版。** 裝備、道具、事件、系統共用同一種排版，外觀和操作都一樣：

| 左 | 右 |
|---|---|
| 清單（道具：每列 3 個的格子），可捲動，上方有篩選 | 選中的項目：圖示或種類、名稱、文字、數值，以及它的動作按鈕 |

沒選任何東西 → 右邊顯示「請選擇道具」（或「請選擇事件」）。切換分頁再回來時保留選擇。

## 3. 分頁 1 — 狀態

```
┌ 狀態 ─────────────────────────────────┬──────────────────────────────────────┐
│ [玩家圖]          Lv 4                │ 屬性                                 │
│ HP   82 / 150  ███████████░░░         │   STR  力量   12                      │
│ EXP  37 / 120  ████░░░░░░  （升級）    │   DEX  靈巧    9                      │
│ ATK  20 (+3)   DEF  7                 │   AGI  敏捷   10                      │
│ 金幣 45    鑰匙  黃 1  藍 0  紅 0       │   VIT  體質   11                      │
│ 樓層 F03  ·  第 1 章                   │   INT  智力    8                      │
│ 武器 見習者法杖   防具 —               │   LUK  幸運    5                      │
│ 功法 引氣 · …   記憶碎片 2             │ （點一個：顯示它的說明）               │
└───────────────────────────────────────┴──────────────────────────────────────┘
```

**Q11 — 2026-10-10 已回答：** 像一般 RPG 一樣擴充狀態；擁有者之後會為它加入新玩法，所以屬性現在就必須存在。
這個分頁顯示兩種數字：

| 種類 | 數值 | 作用 |
|---|---|---|
| **戰鬥數值**（現有） | HP / 最大 HP、ATK、DEF、Lv、EXP、金幣、鑰匙 | 目前戰鬥和門使用的 |
| **屬性**（新增） | STR、DEX、AGI、VIT、INT、LUK，定義在 `stats.json` | 會儲存、存檔、顯示，由升級、道具和裝備提升。**目前還不影響任何東西**：讀取它們的玩法之後才加入 |

ATK 和 DEF 顯示基礎值和裝備、功法的加成，`20 (+3)`（`effectiveAtk()` / `effectiveDef()`）。點一個屬性會在右邊顯示它的說明。
劇情計數器（`counters.json`）仍然達到 `displayAt` 才以文字出現。

**設定檔 `assets/data/stats.json`**（新增）。在這裡新增、刪除或調整屬性順序，狀態分頁、升級和存檔都會跟著改，不用改程式：

```json
{
  "attributes": [
    { "id": "str", "short": "STR", "name": "stat.str.name", "desc": "stat.str.desc", "base": 5, "perLevel": 1 },
    { "id": "dex", "short": "DEX", "name": "stat.dex.name", "desc": "stat.dex.desc", "base": 5, "perLevel": 1 },
    { "id": "agi", "short": "AGI", "name": "stat.agi.name", "desc": "stat.agi.desc", "base": 5, "perLevel": 1 },
    { "id": "vit", "short": "VIT", "name": "stat.vit.name", "desc": "stat.vit.desc", "base": 5, "perLevel": 1 },
    { "id": "int", "short": "INT", "name": "stat.int.name", "desc": "stat.int.desc", "base": 5, "perLevel": 1 },
    { "id": "luk", "short": "LUK", "name": "stat.luk.name", "desc": "stat.luk.desc", "base": 5, "perLevel": 0 }
  ],
  "levelUp": { "expPerLevel": 30, "atk": 2, "def": 1, "maxhp": 10, "freePoints": 0 }
}
```

| 欄位 | 意義 |
|---|---|
| `id` | 屬性的 id；道具和裝備在它們的 `stats` 中用它（`{ "str": 2 }`） |
| `short`、`name`、`desc` | 簡稱，以及 `text.json` 中名稱和說明的文字鍵 |
| `base`、`perLevel` | Lv 1 時的數值，以及每次升級增加多少 |
| `levelUp` | 現在的升級數值，從程式搬出來：所需 EXP = `lv * expPerLevel`，以及每級給的 ATK / DEF / 最大 HP。`freePoints`：每次升級讓玩家自己分配的點數（0 = 沒有；留給之後的玩法） |

**遊戲中：** `Player` 以 id 保存屬性值（隨這輪存檔）；一個函式 `attr("str")` = 基礎 + 等級 + 使用過的道具 + 穿戴的裝備，之後的玩法就讀它。

## 4. 分頁 2 — 裝備

```
┌ 裝備 ───────────────────────────────┬──────────────────────────────────────────┐
│ 穿戴中                              │ [圖示]  雙生短匕  Twin Daggers             │
│  武器 [i] 見習者法杖                │ 蓄力極快、判定帶短小的武器。               │
│  防具 [i] —                         │ ─────────────────────────────────────────  │
│ ─────────────────────────────────── │            目前       換上後              │
│ [ 武器 ] [ 防具 ]   ← 部位篩選      │ ATK        20    →    18   (−2)           │
│ ┌────┐ ┌────┐ ┌────┐                │ 蓄力       慢    →    極快                │
│ │法杖│ │短匕│ │重斧│                │ 判定帶     15    →    10  （較窄）         │
│ │ ✓  │ │    │ │    │                │ 技能       —     →    疾風連刺              │
│ └────┘ └────┘ └────┘                │                                          │
│                                     │ [ 裝備 ]                                 │
└─────────────────────────────────────┴──────────────────────────────────────────┘
```

- **左上：** 每個部位目前穿戴的東西。點一個部位就選擇那個部位的篩選。
- **左下：** 選中部位（**武器** 或 **防具**）擁有的裝備，和道具一樣是每列 3 個的格子；穿戴中的有 ✓。
- **右邊：** 選中的裝備：名稱、說明，以及 **和目前穿戴的比較**：來自 `stat` 的 ATK / DEF，用文字描述來自 `bar`
  區塊的戰鬥長條（蓄力速度來自 `v0` / `vmax` / `rampTime`，判定帶來自 `greenHalf`，最高倍率 `maxMult`），
  以及它給的技能（`actives`）。較好的數值是綠色，較差的是紅色。
- **按鈕：** **裝備**（換上；舊的回到清單），或對穿戴中的按 **卸下**（只限防具；武器欄一定有一把，最差是初始法杖）。
- **天賦**（`equipment.json` 的第三個部位）目前不在這裡顯示（Q15）。
- 換裝免費，只要選單能打開就能換（戰鬥中不行）。

**Q15 — 2026-10-10 已回答：目前只做更換。** 這個分頁選擇要穿哪一件擁有的武器和防具；想要更強的武器，就要買或鍛造另一把。

**之後再做（不在本規劃的階段中）：裝備強化。** 讓擁有的裝備變強，例如 雙生短匕 → +1 → +2，花金幣或材料，是之後另外的工作。
它需要新資料（每一級花多少、加多少），以及這個分頁詳細中的 **強化** 按鈕。在進度報告中以 W26 追蹤。
天賦暫時不放在這個分頁（預設），直到那項工作或擁有者另外決定。

## 5. 分頁 3 — 道具

```
┌ 道具 ───────────────────────────────┬──────────────────────────────────────────┐
│ [ 全部 ] [ 消耗 ] [ 裝備 ] [ 鑰匙 ] │ [大圖示]  生命藥水  Health Potion          │
│ ┌────┐ ┌────┐ ┌────┐                │ ─────────────────────────────────────────  │
│ │藥水│ │寶石│ │卷軸│   ▲            │ 回復 50 HP。                              │
│ │ x2 │ │ x1 │ │ x1 │   █            │ 效果   HP +50                            │
│ └────┘ └────┘ └────┘   │ 捲動       │ 價格   8 金幣                             │
│ ┌────┐ ┌────┐ ┌────┐   │            │ 持有   2                                  │
│ │黃鑰│ │法杖│ │短匕│   ▼            │                                          │
│ │ x1 │ │ ✓  │ │    │                │ [ 使用 ]  [ 丟棄 ]                        │
│ └────┘ └────┘ └────┘                │                                          │
└─────────────────────────────────────┴──────────────────────────────────────────┘
```

- **格子（左）：** 玩家 **擁有** 的道具（Q13），**每列 3 個**，列數不限，**可捲動**（滑鼠滾輪、觸控拖曳、方向鍵）。
  每格：圖示、數量標記（**x2**：相同道具疊成一格；現在每一個都是單獨一列）、穿戴中的裝備有 ✓、重要道具有 🔒。
  上方的篩選：**全部**、**消耗**（消耗品）、**裝備**（武器和防具）、**鑰匙**。
- **詳細（右），點選道具時：** 大圖示、名稱（目前語言）、說明、可讀的 **效果**（`HP +50`、`ATK +3`、`STR +2`……，來自它的 `stats`）、
  **價格**、持有數量，以及適用的按鈕：

  | 道具 | 按鈕 |
  |---|---|
  | 消耗品（藥水、寶石、卷軸……） | **使用**、**丟棄** |
  | 武器／防具 | **裝備**（穿戴中則為 **卸下**），附上和裝備分頁相同的比較；**丟棄** 只限未穿戴且非重要的 |
  | 重要道具（鑰匙、劇情道具） | 不能丟棄：按鈕顯示為灰色，並標示「重要道具無法丟棄」 |

  **丟棄** 會先確認（「丟棄 生命藥水？丟棄後無法找回。」）。穿戴中的裝備永遠不能丟棄。
- **按鍵：** Enter = 第一個按鈕，Del = 丟棄。

**Q12 — 2026-10-10 已回答：** 每個道具的價格來自設定檔，而且 **所有道具放在同一個檔案**。`assets/data/items.json`
就是那個檔案：遊戲中每一種道具（地圖道具、鑰匙、消耗品、武器、防具、天賦、劇情道具）各一筆紀錄：

```json
{
  "potion_red": {
    "type": "consumable", "sprite": "potion_red.png",
    "name": "item.potion_red.name", "desc": "item.potion_red.desc",
    "stats": { "hp": 50 }, "price": 8, "important": false
  },
  "twin_daggers": {
    "type": "weapon", "sprite": "twin_daggers.png",
    "name": "item.twin_daggers.name", "desc": "item.twin_daggers.desc",
    "stats": { "atk": -2, "dex": 2 }, "price": 120,
    "bar": { "v0": 30, "vmax": 320, "rampTime": 1.0, "greenHalf": 10 }, "actives": ["swift_stab"]
  },
  "key_yellow": {
    "type": "key", "sprite": "key_yellow.png",
    "name": "item.key_yellow.name", "desc": "item.key_yellow.desc",
    "stats": { "key_yellow": 1 }, "price": 10, "important": true
  }
}
```

| 欄位 | 意義 |
|---|---|
| 紀錄的鍵 | 道具 id，到處都用它：地圖上（`item:potion_red`）、商店、存檔、獎勵 |
| `type` | `consumable`、`key`、`weapon`、`armor`、`talent`、`story`；決定篩選、按鈕和裝備部位 |
| `sprite` | 圖示 |
| `name`、`desc` | `text.json` 中的 **文字鍵**（六種語言放在那裡），不是直接寫在這裡的文字 |
| `stats` | 它給什麼：消耗品是使用時（`hp`、`atk`、`def`、`gold`、`exp`、鑰匙）；裝備是穿戴期間；`stats.json` 的任何屬性 id 都可以（`str`、`dex`……） |
| `price` | 金幣價格，顯示在詳細中；也是商店的價格 |
| `important` | `true` = 不能丟棄（鑰匙、劇情道具） |
| `bar`、`actives` | 只限武器／防具：戰鬥長條設定和給的技能（從 `equipment.json` 搬過來） |

**其他檔案的改變：**

- `equipment.json` 併入 `items.json`（`type` 為 weapon / armor / talent），然後移除。
- `store.json` 只保留商店 **賣什麼**（道具 id 清單）、解鎖樓層和價格規則；名稱、圖示、說明和它自己的 id（`potion_hp`）都移除。
  商店收道具的 `price`；如果保留「每買一次加倍」的規則，就從這個價格開始加倍。
- 直接寫在檔案中的六語 `name` / `desc` 移到 `text.json`，鍵為 `item.<id>.name` / `.desc`。
- footprint 測試（每層每個道具都是遊戲會撿起的東西）改成對照新檔案；另加一個檢查，道具缺 `price`、`type` 或文字鍵時失敗。

## 6. 分頁 4 — 事件

```

│ ★ 第 1 章 · 我為何舉劍              │ ─────────────────────────────────────────  │
│ ◆ 石巨人退治                        │ 村長想答謝把孫子帶回家的人。                 │
│ ● 村長的謝意                   ◀    │ 他在古井旁等著。                            │
│ ✓ 迷途的孩子                        │                                          │
│ ✓ 古井的低語                        │ 相關事件                                  │
│                                     │   迷途的孩子 ✓                             │
│                                     │   古井的低語 ✓                             │
└─────────────────────────────────────┴──────────────────────────────────────────┘
```

**Q14 — 2026-10-10 已回答：** 詳細只顯示 **標題** 和 **說明**，如果和其他事件相關，**只顯示那些事件的名稱**。
所以每個事件、任務和章節都有標題和說明（文字鍵）；這個分頁不顯示進度數字、下一步或獎勵。

- **列出什麼：** 只列玩家 **已開始** 或 **已完成** 的：目前的章節、已接受的任務、已開始的事件，以及已完成的。
  還沒提供的任務、還沒遇到的事件永遠不列出。
- **上方的切換：** **未完成**（預設）：目前進行中的。**全部**：進行中的在前，接著是已完成的（✓、灰色、最新的在前）。
- **每一列：** 種類標記（★ 章節、◆ 任務、● 事件、✓ 已完成）和標題。
- **詳細（右），點選一列時：**
  1. 標題；
  2. 說明；
  3. **相關事件：** 和這一項連結的事件標題（已完成的有 ✓）。點一個會選中它（如果它有列出）。
     玩家還沒遇到的相關事件顯示為 **？？？**，名稱不會劇透後面的內容。沒有相關事件時不顯示這個標題。
- **新增或完成一項** 時，行走畫面會閃一下「事件紀錄已更新」提示，≡ 和事件分頁上也會有小點，直到打開為止。

## 7. 分頁 5 — 系統

現在 ≡ 選單的各列，加上原本在別處的兩個按鈕。會打開頁面的列（功法、鍛造、村莊、設定）把頁面 **顯示在分頁右側**；
商店和現在一樣打開商店畫面，關閉商店後回到這個分頁。

```
┌ 系統 ───────────────────────────────┬──────────────────────────────────────────┐
│  商店                  •            │ （選中列的頁面：功法、鍛造、村莊、設定；  │
│  功法                  2 點         │   或一行說明這一列做什麼）                 │
│  鍛造                               │                                          │
│  村莊                               │                                          │
│  存檔                               │                                          │
│  設定                               │                                          │
│  全螢幕                開／關        │                                          │
│  回到標題                           │                                          │
└─────────────────────────────────────┴──────────────────────────────────────────┘
```

| 列 | 原本 | 說明 |
|---|---|---|
| 商店 | HUD 金幣按鈕 | 解鎖前為灰色，並顯示何時解鎖（按鈕原本的 `locked` 狀態） |
| 功法、鍛造、村莊、存檔、設定、回到標題 | ≡ 清單（`mainMenuOrder()`） | 相同的頁面和排序規則（舊選單隱藏的列仍隱藏） |
| 全螢幕 | 網頁的 ⛶ 按鈕 | 網頁和桌機；Android 上隱藏（永遠全螢幕）。顯示目前狀態 |

**在遊戲裡切換全螢幕（網頁）。** 瀏覽器只允許在點擊或按鍵的處理函式中進入全螢幕，但點 RmlUi 的一列是在下一個遊戲畫面才處理。
所以這一列分兩半運作：**按下**（mousedown / touchstart）時遊戲通知網頁（`EM_ASM` → `tomsFullscreenArm()`），
網頁自己的 **pointerup** / **keyup** 監聽器在同一個手勢中呼叫 `requestFullscreen()` / `exitFullscreen()`。
桌機則切換 `SDL_SetWindowFullscreen`。網頁把 `fullscreenchange` 回報給遊戲（`jsFullscreenChanged`），
讓這一列顯示開／關，玩家用瀏覽器自己的 Esc 離開時也一樣。
