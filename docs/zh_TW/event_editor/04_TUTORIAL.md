# 04 — 教學：建立事件、看懂關係、找出並修正問題

> 英文原文：[04_TUTORIAL.md](../../event_editor/04_TUTORIAL.md)

本教學以真實 TOMS 事件資料的副本，分幾個部分走過規劃中的編輯器：

| 部分 | 步驟 | 你要做的事 |
|---|---|---|
| 1. 建立事件 | 1–6 | 新增 `ev_village_scarecrow`，連接到 F02 和 F04，看關係圖，儲存 |
| 2. 找出問題 | 7–9 | 開啟「問題」分頁；檢查一個孤立事件和一個缺少的事件 ID |
| 3. 解決問題 | 10–13 | 連接孤立事件、建立缺少的事件、一次補齊整章、儲存 |
| 4. 連接樓層 | 14–20 | 給 F50 第二座通往新樓層 F96 的上樓梯，用事件鎖住它，儲存 |
| 5. 事件邏輯 | 21–29 | 一個變數、達到 2 之後交談就觸發的事件、一個直接連結、節點圖、儲存 |

想自己試試，請開啟 [tools/web_editors/index.html](../../../tools/web_editors/index.html)（事件編輯器；⇄ 切換到關卡編輯器）。頁面有英文和
繁體中文：用上方列的 🌐 選單選擇。選擇會被記住，
`event_editor.html?lang=zh_TW` 或 `?lang=en` 會直接用該語言開啟。每一步都有
**示範給我看** 按鈕，會幫你完成那一步。**重設教學** 會從頭開始。

教學面板只有第一次會自己打開。之後它會保持隱藏，把空間留給編輯器；上方列的 **📘 教學**
可以打開或關閉它，面板中的 **◀ 隱藏** 會關閉它。
`event_editor.html?tutorial=1` 一定會打開它。

**▶ 播放示範** 會自己跑完剩下的所有步驟，而且是透過真正的控制項：它會在欄位中打字、
勾選樓層、點按鈕和關係圖節點。播放時：

- **示範主控台**（右下角）顯示 **NEXT**：下一個動作是什麼、在哪裡，並有一條倒數的進度條。
  下方是計時的紀錄，列出每個完成的動作（✓）和每個完成的步驟。
  *紀錄* 按鈕可以把紀錄收起來。
- 黃色的**聚光燈**會讓視窗其他部分變暗，並框出下一個動作要用的控制項，
  標上它所在的區域（例如 *樓層選擇器 · ch_01* 或 *屬性面板 · 類型*）。
- 速度框可設 0.5×、1× 或 2×。**■ 停止**（或 Esc）會在目前動作完成後暫停，
  ▶ 播放示範會從那一步繼續。

資料是副本，由 [tools/web_editors/make_data.py](../../../tools/web_editors/make_data.py) 產生（見文末的 *資料副本*）。
不會寫入 `assets/` 任何東西。

編輯器視窗有這些部分：

| 部分 | 位置 | 用途 |
|---|---|---|
| 事件樹 | 左側 | 事件池和它們的事件；**+ 新增事件**；紅色的 *無事件池* 群組列出缺少的 ID。點任一群組標題可以收合，或用 *全部展開* / *全部收合*。上方的篩選框（Ctrl+F）可依 ID、任一語言的文字、類型、事件池或樓層找事件，還有類型下拉選單和 *只看有問題的* |
| 屬性面板 | 中央 | 選取事件的欄位、樓層和文字，或缺少 ID 的修正方式 |
| 關係圖 | 下方分頁 | 什麼連到什麼；*聚焦*，或依章節的 *全圖* |
| 問題 | 下方分頁 | 驗證器的清單，每一列都有修正按鈕 |
| 樓層圖 | 下方分頁 | 每章一列，每座樓梯一個箭頭；上鎖的樓梯是金色虛線。點樓層可編輯它的樓梯 |
| 歷程 | 右側 | 每次編輯，方便你復原 |

# 第一部分 — 建立事件

## 第 1 步 — 建立新事件

點事件樹上方的 **+ 新增事件**，或事件池名稱旁的 **+**。請用
`pool_act01` 旁的 **+**。

`pool_act01` 中會出現一個空白事件 `ev_new_event_1`，帶有綠色的 **NEW** 標籤，屬性面板也會
選取它。它顯示 ⚠，因為還沒有任何樓層能抽到它。

> **哪個事件池？** 事件池只是把相關的事件放在同一個檔案：`pool_act01` 放村莊的事件，
> `pool_act02` 放森林，`pool_act03` 放城門，`pool_common` 放共用的。它並不
> 限制事件出現在哪裡。決定的是你在第 4 步連接的樓層，可以來自任何章節。

## 第 2 步 — 命名並選擇類型

1. 在 **eventId** 輸入 `ev_village_scarecrow` 後按 Tab。
2. 在 **類型** 選 `whisper`。

**文字鍵** 會自己跟著 ID 改變：`ev_village_scarecrow.text`。

ID 會在你打字時檢查：

| 你輸入 | 你會看到 |
|---|---|
| `a<b` | *任何名稱都可以，中文也行（例如 ev_village_scarecrow 或 稻草人），但不能是空的、頭尾不能有空白，也不能有 " ' < > & \| \ /* |
| `ev_village_well` | *ev_village_well 已存在於 pool_act01* |

類型有 `relic`、`whisper`、`cache`、`trap`、`rescue`、`merchant_echo` 和 `memory_shard`。
類型決定它在事件樹和關係圖中的顏色。

## 第 3 步 — 撰寫文字

輸入玩家讀到的台詞：

| 語言 | 文字 |
|---|---|
| zh_TW | 稻草人轉過頭來看你。 |
| en | The scarecrow turns its head to watch you. |

**預覽** 框會在你打字時，以遊戲對話框的樣式顯示這句台詞。留空的語言在問題清單中算作
*未翻譯*；不會阻止你儲存。

## 第 4 步 — 連接到樓層

1. 在 **可抽到此事件的樓層** 底下點 **+ 新增樓層…**。
2. 清單依章節分組，方便找樓層。任何樓層都可以勾選。
3. 勾選 **F02** 和 **F04**，再按 **連接**。

會出現兩個標籤 `F02 ch_01` 和 `F04 ch_01`。在關係圖中，F02 和 F04 會長出兩條綠色連線
指向新事件。事件樹中的 ⚠ 消失了。

- 要中斷某個樓層，點它標籤上的 ✕。
- 不同章節的樓層可以抽到同一個事件。編輯器不會對此發出警告，
  因為一層樓可以容納好幾個角色的故事。

## 第 5 步 — 觀看關係圖

關係圖由左往右讀：

```
FLOORS      POOLS        EVENTS                 TEXT KEYS
 F02 ─────────────────▶ ev_village_scarecrow ──▶ ev_village_scarecrow.text
 F04 ─────────────────▶      ▲
          pool_act01 ────────┘
```

- **樓層 → 事件** 的連線表示該樓層能抽到這個事件（樓層檔列出了它）。
- **事件池 → 事件** 的連線表示這個事件定義在那個事件池檔中。
- **事件 → 文字鍵** 的連線表示它的文字放在 `text.json` 的那個鍵底下。

它有兩種模式：

| 模式 | 顯示 |
|---|---|
| **聚焦：選取項** | 選取的事件、它的事件池、它的樓層和文字鍵。那些樓層抽到的其他事件會淡化顯示，讓你看出它和哪些事件共用樓層 |
| **全圖** | 所有事件池和事件，以及樓層 F01–F21（有事件池的章節）。選取的事件會發光；新事件標記為 **NEW** |

切到 **全圖**，然後點 **F02**。F02 能抽到的所有東西都會亮起來：
`ev_village_chapel_dust`、`ev_village_ledger`、`ev_village_well` 和你的新事件。狀態列
也會列出相同內容。點一個事件節點，就會在屬性面板中選取它。

## 第 6 步 — 儲存

按 **儲存** 或 Ctrl+S。對話框會顯示每個將要改變的檔案。新增的行是綠色，刪除的行是紅色：

**`assets/data/events/pool_act01.json`**
```diff
   "events": [
     ...
     { "eventId": "ev_village_old_plough", "kind": "cache", "text": "ev_village_old_plough.text" },
+    { "eventId": "ev_village_scarecrow", "kind": "whisper", "text": "ev_village_scarecrow.text" }
   ]
```

**`assets/data/story/floors/F02.json`**（`F04.json` 也一樣）
```diff
   "events": [
     "ev_village_chapel_dust",
     "ev_village_ledger",
     "ev_village_well",
+    "ev_village_scarecrow"
   ],
```

**`assets/data/text.json`**
```diff
   "strings": {
     ...
+    "ev_village_scarecrow.text": { "zh_TW": "稻草人轉過頭來看你。", "en": "The scarecrow turns its head to watch you." }
   }
```

點 **寫入 4 個檔案**。編輯器會先把每個檔案複製到備份資料夾，再寫入。
歷程面板顯示 *已儲存 4 個檔案*，事件分頁上的 • 也會消失。

如果還有問題，對話框會說有幾個，但仍然讓你儲存。

# 第二部分 — 找出問題

## 第 7 步 — 開啟「問題」分頁

點關係圖上方的 **問題**。驗證器在每次編輯後都會執行。以今天的資料，它會顯示：

| 規則 | 數量 | 意義 |
|---|---|---|
| ⛔ 缺少的事件 ID | 92 | 樓層列出了一個沒有任何事件池定義的 ID |
| ⚠ 孤立事件 | 4 | 事件池定義了一個沒有任何樓層列出的事件 |
| ⓘ 未翻譯 | 34 | `en` 是空的，或和 `zh_TW` 相同（點它的標籤才會顯示） |

其他規則（缺少文字鍵、未設類型、佔位文字）目前是 0；它們會在你工作時出現。
上方的標籤可以開關每條規則。標籤下方的列依章節把缺少的 ID 分組：
`ch_04: create 23`、`ch_05: create 16` … `ch_10: create 11`。

點任一列，編輯器就會選取那個 ID，並在關係圖中以 *聚焦* 模式顯示它。

## 第 8 步 — 檢查孤立事件

點 **ev_village_bell_rope · 孤立事件** 這一列。

- 屬性面板顯示橘色橫幅：*沒有任何樓層能抽到這個事件，所以它永遠不會在遊戲中出現*。
- 關係圖顯示 `pool_act01 → ev_village_bell_rope → ev_village_bell_rope.text`，而 FLOORS 欄中
  什麼也沒有。孤立事件就是沒有任何來自樓層的連線指向它的節點。

## 第 9 步 — 檢查缺少的事件 ID

點 **ev_cavern_echo_wall · 缺少的事件 ID** 這一列。

```
FLOORS                      EVENTS                         TEXT KEYS
 F38 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄▶ ⛔ ev_cavern_echo_wall          ev_cavern_echo_wall (placeholder)
 F41 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄▶        (red: no pool)
```

- 紅色虛線來自 F38 和 F41（`ch_06`）。它們指向一個沒有任何事件池定義的 ID，所以
  任一樓層抽到它時，都沒有事件可以顯示。
- `text.json` 只在不帶後綴的 ID 底下有一個佔位文字，標記為 `_todo`，內容就是 ID 本身。
- 屬性面板顯示修正方式：**在 pool_act06 中建立**、**建立 ch_06 全部 14 個缺少的 ID**，
  以及 **從樓層移除**。

這是資料中最大的問題：樓層 F22–F70（ch_04 到 ch_10）列了 92 個這樣的 ID，
因為那些章節還沒有事件池檔。

# 第三部分 — 解決問題

## 第 10 步 — 修正孤立事件：連接它

1. 選取 `ev_village_bell_rope`。
2. 點 **+ 新增樓層…**。
3. 勾選 **F06**，再按 **連接**。

F06 會長出一條綠色連線，這列孤立事件也離開問題清單（4 → 3）。如果不需要這個事件，
另一種修正是點它那一列的 **刪除**。

## 第 11 步 — 修正缺少的 ID：建立事件

1. 選取 `ev_cavern_echo_wall`，點 **在 pool_act06 中建立**。編輯器會：
   - 建立 `pool_act06`（在事件樹中標記 NEW），因為 ch_06 還沒有事件池檔；
   - 加入紀錄 `{ "eventId": "ev_cavern_echo_wall", "kind": "", "text": "ev_cavern_echo_wall" }`。
     文字鍵用的是現有的佔位文字，所以樓層、事件池和文字都對得上，不需要新的鍵。
2. 紅色節點變成一般事件，並有兩個警告指向它：⚠ *未設類型* 和
   ⚠ *佔位文字*。
3. 類型選 **whisper**。
4. 把 zh_TW 的佔位文字換成 `洞壁傳回的回聲，比你的聲音晚了一拍。`，en 換成
   `The cavern wall echoes you back, one beat too late.`

缺少的事件 ID 從 92 變成 91。

如果 ID 是打錯字，或這個事件已經被刪掉，正確的修正就是 **從樓層移除**。

## 第 12 步 — 一次修正整章

在 **問題** 中點 **ch_04: create 23**。編輯器會在一個復原步驟中，建立 ch_04 各樓層列出的
所有 ID：

| ID | 放到 | 類型 |
|---|---|---|
| `ev_common_*_v2` … `_v5`（15 個） | `pool_common` | 從原版複製，例如 `ev_common_cache_wall_v3` → `cache` |
| `ev_library_*`（8 個） | 新的 `pool_act04` | 從名稱猜測（`…_whisper` → whisper）；猜不到就留空 |

缺少的事件 ID 從 91 變成 68。取而代之出現兩種警告：23 個 *佔位文字* 和
5 個 *未設類型*。那就是剩下的撰寫工作。每一列都有 **撰寫文字** 或 **選擇類型**
按鈕，會直接跳到該欄位。

## 第 13 步 — 儲存並檢查

按 **儲存**。這次對話框列出 5 個檔案：

- `pool_act04.json（新檔案）` 和 `pool_act06.json（新檔案）`，整個檔案都是綠色；
- `pool_common.json`，加了 15 筆變體紀錄；
- `F06.json`，現在列出了 `ev_village_bell_rope`；
- `text.json`，`ev_cavern_echo_wall` 的佔位文字變成真正的台詞。

寫入它們。狀態列顯示剩下的：68 個錯誤（ch_05 到 ch_10，用和 ch_04 一樣的方法修正），
以及新事件的類型和文字警告。

# 第四部分 — 連接樓層

格式和遊戲規則在 [05_FLOOR_LINKS.md](05_FLOOR_LINKS.md)。

## 第 14 步 — 開啟樓層圖

點關係圖上方的 **樓層圖**。每一列是一章（ch_01 … ch_10），每個方框是一層樓，每個
箭頭是一座樓梯。今天每層樓都只有一座上樓梯和一座下樓梯，所以整張圖是一條 F01 → F70 的鏈。

## 第 15 步 — 選取樓層 F50

點 **F50**。樓層屬性面板顯示它的章節、它的 **樓梯**（↑ F51、↓ F49，取自舊的
`nextFloor` 鏈）、*從哪裡到達*，以及它能抽到的事件（紅色 = 沒有事件池定義的 ID）。

## 第 16 步 — 加一座通往 F96 的上樓梯

點 **+ 新增樓梯**，保持 **↑ 上**，目標輸入 `F96` 後按 Tab。F96 不存在，
所以這一列顯示 *⛔ F96 還不存在*，圖上畫出一個紅色的 ⛔ F96 替身，問題清單也
列出 ⛔ *缺少的樓層*。

## 第 17 步 — 建立樓層 F96

點 **建立樓層 F96**。新樓層沿用 F50 的章節（`ch_08`），沒有事件，並有一座 ↓ 樓梯
回到 F50。*缺少的樓層* 錯誤消失了。

## 第 18 步 — 用事件鎖住樓梯

在 F96 那一列，把 **完成後解鎖** 設為 `ev_common_relic_road`。清單會先列出 F50
能抽到的事件。在遊戲中，這座樓梯會一直隱藏，直到玩家完成那個事件。

如果你選了一個沒有任何可到達樓層能抽到的事件，例如孤立事件
`ev_village_grave_new`，F96 會變成 ⚠ *無法到達*：這座樓梯永遠打不開。選了沒有事件池
定義的 ID，會出現 ⛔ *未知的解鎖事件*。

## 第 19 步 — 觀看樓層圖

F50 → F96 是一條標著 🔒 `ev_common_relic_road` 的金色虛線箭頭；F50 → F51 沒有改變。點
**F96**：*從哪裡到達* 顯示 ↑ F50 🔒。

## 第 20 步 — 儲存樓層

**儲存** 顯示兩個檔案：

```diff
 assets/data/story/floors/F50.json
   "nextFloor": "F51",   (kept for older builds; stairs wins)
+  "stairs": [
+    { "dir": "up", "to": "F51" },
+    { "dir": "down", "to": "F49" },
+    { "dir": "up", "to": "F96", "unlock": { "eventDone": "ev_common_relic_road" } }
+  ],

 assets/data/story/floors/F96.json  (new file)
+{
+  "id": "F96", "act": "ch_08", "role": "normal",
+  "events": [],
+  "stairs": [
+    { "dir": "down", "to": "F50" }
+  ]
+}
```

（`nextFloor` 保留給舊版遊戲；以 `stairs` 為準。）你沒動過的樓層只保留它們的 `nextFloor`，不會被重寫。

# 第五部分 — 事件邏輯

格式、規則和執行期的工作在 [06_EVENT_LOGIC.md](06_EVENT_LOGIC.md)。

| 步驟 | 你要做的事 | 寫入的內容 |
|---|---|---|
| 21 | 開啟 **變數** | — |
| 22 | 新增 `well_clues`（int，從 0 開始，每局重置） | `story/vars.json`（新檔案） |
| 23–24 | 在 `ev_village_well` 和 `ev_village_ledger` 上：*接著做* → 把變數 `well_clues` 加 1 | `"actions": [{ "type": "addVar", … }]` |
| 25 | 新事件 `ev_village_elder_thanks`：玩家和 `villager`（F07、F35）交談時觸發，在 `well_clues ≥ 2` 時啟用，把計數器 `insight` 加 1 | `trigger`、`requires`、`actions` |
| 26 | *接著觸發* → `ev_village_grave_new`，它的觸發方式變成 *由其他事件連結* | `"next": [...]`、`"trigger": { "on": "chain" }`；墳墓事件不再是孤立事件 |
| 27 | 開啟 **邏輯圖**：節點編輯器。點村長的節點，讓它的連線動起來 | — |

## 資料副本

編輯器使用事件資料的副本，從不直接使用 `assets/`：

```
python tools/web_editors/make_data.py
```

它讀取 `assets/data/events/pool_*.json`、樓層設定 `assets/data/story/floors/F??.json`、`text.json` 中的
事件字串，以及變數、計數器、旗標和類型，寫入頁面載入的 `tools/web_editors/data.js`。
`tools\web_editors\serve.cmd` 每次啟動都會執行它，所以編輯器開啟時永遠是目前的資料；不用伺服器時，
資料改變後請執行 `tools\web_editors\refresh_data.cmd`。本文件中的數字來自
2026-10-05 製作的副本。
