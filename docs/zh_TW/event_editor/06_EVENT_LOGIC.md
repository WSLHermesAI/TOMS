# 06 — 事件邏輯：觸發、條件、動作、連結

> 英文原文：[06_EVENT_LOGIC.md](../../event_editor/06_EVENT_LOGIC.md)

**現況：** 設計，以及編輯器的 mockup（[tools/web_editors/event_editor.html](../../../tools/web_editors/event_editor.html)，第五部分，
和它的 **邏輯圖** 節點編輯器）。遊戲還不會執行這些；第 6 節列出執行期的工作。

事件不只是一個 ID、一個文字鍵和能抽到它的樓層。它可以：

- 在玩家踩上它的格子、**跟某人交談**、**某個變數改變**時**觸發**，或在
  另一個事件**連結**到它時觸發；
- **只在**變數、計數器、旗標或已完成的事件符合條件時**啟用**；
- **做**事情：設定或增加變數、增加計數器、設定旗標、給予物品；
- **直接觸發其他事件**（`next`）。

## 1. 格式

新欄位放在事件池檔中該事件的紀錄上。沒有這些欄位的紀錄不受影響，
維持今天的行為（在它的格子上觸發，沒有條件，沒有動作）。

```json
{
  "eventId": "ev_village_elder_thanks",
  "kind": "rescue",
  "text": "ev_village_elder_thanks.text",
  "trigger":  { "on": "talk", "npc": "villager" },
  "requires": { "type": "varAtLeast", "var": "well_clues", "value": 2 },
  "actions":  [ { "type": "addCounter", "counter": "insight", "delta": 1 } ],
  "next":     [ "ev_village_grave_new" ]
}
```

### trigger：什麼時候觸發

| `trigger` | 觸發時機 | 需要格子 |
|---|---|---|
| 沒有，或 `{ "on": "step" }` | 玩家踩上它的格子（今天的行為） | 是 |
| `{ "on": "talk", "npc": "villager" }` | 玩家和那個 NPC 交談（對話關閉之後） | 否 |
| `{ "on": "varChanged", "var": "well_clues" }` | 那個事件變數改變時 | 否 |
| `{ "on": "chain" }` | 只在另一個事件的 `next` 連結到它時 | 否 |

不管觸發方式為何，事件只在 `requires` 為真時觸發，而且每局只觸發一次（之後可以為可重複的事件
加上 `"once": false`）。

### requires：什麼時候啟用

`requires` 使用遊戲已經在評估的條件格式（`src/core/engine/condition.cpp`）：
一個葉節點，或由葉節點組成的 `all` / `any` / `not`。編輯器把一個葉節點、或由葉節點組成的 `all` 顯示成多列；
其他任何寫法都原封不動保留，並以 JSON 顯示。

| 葉節點 | 意義 | 狀態 |
|---|---|---|
| `{ "type": "varAtLeast", "var": "x", "value": 2 }` | 事件變數 x ≥ 2 | **新** |
| `{ "type": "varEquals", "var": "x", "value": 2 }` | 事件變數 x = 2 | **新** |
| `{ "type": "counterAtLeast", "counter": "insight", "min": 1 }` | 劇情計數器 ≥ 1 | 已有 |
| `{ "type": "runFlagSet", "flag": "flag_truth_told" }` | 某個旗標已設定 | 已有 |
| `{ "type": "runFlagSet", "flag": "event_ev_village_well" }` | 某個事件已完成 | 已有（見 6.2） |

其他現有的葉節點（`choiceMade`、`itemHeld`、`statAtLeast`、`stageCleared`、…）也都能用。

### actions：它做什麼

| 動作 | 意義 | 狀態 |
|---|---|---|
| `{ "type": "addVar", "var": "x", "delta": 1 }` | 增加事件變數 | **新** |
| `{ "type": "setVar", "var": "x", "value": 3 }` | 設定事件變數 | **新** |
| `{ "type": "addCounter", "counter": "insight", "delta": 1 }` | 增加劇情計數器（有上下限） | 已有（對話動作） |
| `{ "type": "setFlag", "flag": "flag_truth_told" }` | 設定本局旗標 | **新**動詞；`run_.setFlag` 已有 |
| `{ "type": "give", "itemId": "gem_def" }` | 給予物品 | 已有（對話動作） |

### next：直接連結

`next` 依序列出在這個事件之後立刻觸發的事件。每個事件仍會檢查自己的 `requires`。

### 事件變數：`assets/data/story/vars.json`（新）

```json
{ "well_clues": { "type": "int", "default": 0, "scope": "run" } }
```

`scope` 依照 `flags.json`：`run` 在開新遊戲和轉生時重置，`meta` 在轉生後保留。
計數器（`counters.json`）和旗標（`flags.json`）保留它們自己的檔案；事件也可以讀寫
它們。

## 2. 範例：村長的謝意（教學第五部分）

```
ev_village_well   ──+1──▶ ◆ well_clues ──≥ 2──▶ ev_village_elder_thanks ──then──▶ ev_village_grave_new
ev_village_ledger ──+1──▶        ▲                   ▲            │
                                                💬 villager       └──+1──▶ ▲ insight
```

找到水井和帳冊各會加一條線索。兩者都找到後跟村民交談，會觸發
村長的謝意，它會增加 insight，並直接觸發墳墓事件。那個事件不需要格子，所以
它不再是孤立事件。

## 3. 編輯器

- **屬性面板 → 邏輯：** *觸發時機*（踩到 / 和某個 NPC 交談並顯示它所在的樓層 / 變數改變 /
  連結）；*只在以下條件啟用*（多列：對象、≥ 或 =、數值）；*接著做*（多列：動作、目標、數量）；
  *接著觸發*（連結的事件，點一個就會開啟）；*被誰觸發*（誰連結到它）。
- **變數分頁：** 事件變數（建立、預設值、範圍、刪除）、計數器和旗標，每一個都有
  *被誰改變* 和 *被誰讀取*。
- **邏輯圖分頁：一個節點編輯器**，仿 [thedmd/imgui-node-editor](https://github.com/thedmd/imgui-node-editor)
  （MIT）的 Blueprint 風格：
  - 節點有事件（輸入：▶ 觸發和條件；輸出：接著 ▶、*完成* 和動作）、事件變數、
    計數器、旗標和 NPC；接腳 ▶ 代表「觸發」，● 代表數值，連接後變成實心；
  - 貝茲曲線連線：白色觸發事件，紫 / 青 / 紅 / 金分別傳遞變數 / 計數器 / 旗標 /
    「事件完成」；選取節點的連線會有動畫；
  - **把接腳拖到接腳來連接**：合適的接腳會亮綠色，連線編輯的資料和
    屬性面板相同（交談 → 觸發 設定觸發方式，接著 → 觸發 加入 `next`，數值 → 條件，
    動作 → 變數）。把連線放在空白處，會跳出合適節點的選單；
  - 右鍵：新增節點；點一條連線再按 Delete 可刪除；拖曳節點；框選；右鍵拖曳
    平移；滾輪縮放；F 符合視窗；⛶ 最大化。節點位置存在瀏覽器中（不在遊戲
    資料裡）。
- **數值關係圖分頁：** 每個事件變數、計數器和旗標在中間，改變它的事件在
  左邊，讀取它的事件在右邊，並有標記 ✎ 被誰改變 · 👁 被誰讀取 · ⇄ 相關聯的
  數值（共用某個事件的數值）。可依名稱和種類篩選；*顯示沒有被使用的數值* 會加入其餘的。
  **滑鼠停在**數值上：顯示有幾個事件改變它、讀取它、在它改變時觸發，以及它和哪些數值
  相關聯；沒有關聯的都會淡化。同樣的提示也會出現在變數分頁的數值名稱上，
  以及邏輯圖的數值節點上。
- **分類和篩選：** 每個事件變數、計數器和旗標都可以有 `category`
  （`"category": "village/clues"`，存在 `vars.json`、`counters.json` 或 `flags.json` 中；`/` 用來建立
  子分類）。沒有分類時，數值會自動分組：旗標依它 `setBy` 中的章節
  （`Chapter ch_03`），計數器歸為 *劇情計數器*，其餘歸為 *未分類*。**變數** 分頁最上方是
  *新增變數* 那一列（新增的變數會反白顯示）。選 *所有分類* 時，數值以一份不分組的清單列出（事件變數、
  計數器、旗標，依名稱排序）；選了某個分類時，則在分類標題底下列出。新增那一列下方有分類輸入框，附 **+ 建立分類**（空的分類會以
  `"_categories": [...]` 存在 `vars.json` 中，直到有數值使用它）、**✎ 分類改名** 和 **🗑 刪除分類**。改名會用對話框詢問
  新名稱，並把該分類及其子分類的每個數值移過去（改成已存在的名稱會合併兩者）。刪除會用對話框列出
  分類中的內容並詢問：**刪除這 N 個事件變數**（計數器和旗標永遠不會被刪除，因為章節、對話和遊戲都會
  用到；它們只會拿掉分類；使用了被刪變數的事件會顯示為問題），或 **改為未分類**（全部保留，只拿掉
  分類，每個數值回到自動分組）。*劇情計數器* 這類自動分組不能刪除。每個操作都是一個復原步驟。**一次處理多個數值：** 勾選各列（標題列的核取方塊會勾選所有
  顯示的數值；Shift+點擊可勾選一段範圍），然後在出現的列中輸入或選擇分類並按 **套用**，或按
  **改為未分類**。計數器和旗標也可以移動；算一個復原步驟（標題可收合；✎ 會重新命名分類和它的子分類；每一列和建立變數時都可以
  編輯分類）。變數分頁和數值關係圖共用同一個篩選：文字（名稱、分類、說明、HUD 標籤、
  由誰設定）、分類（上層分類包含它的子分類）和種類標籤。數值關係圖會顯示分類標題，
  條件和動作的選擇器也依分類把事件變數分組。遊戲會忽略這個多出來的欄位（它
  逐欄讀取 `counters.json`，而且完全不載入 `flags.json`）。
- **數值分頁：** 點一個數值（或在邏輯圖中雙擊它的節點），會在它自己可關閉的分頁中
  開啟：`◆ well_clues ✕`。這個分頁可以編輯它的資料，並用小地圖列出它的關聯：
  - 事件變數：名稱（改名會更新所有使用它的動作、條件和觸發）、種類、
    預設值、範圍、說明（zh_TW / en）；刪除；
  - 計數器：HUD 標籤（zh_TW / en）、*在 HUD 顯示的門檻*（`displayAt`）、上下限；
  - 旗標：範圍、*由誰設定*。`setBy` 指名某個事件（`ev_…`）的旗標，算作被那個事件改變。
  - 所有種類：分類。

  計數器和旗標不能在這裡改名：章節檔、對話檔和遊戲程式碼都用它們的
  名稱。**儲存…** 會把 `vars.json`、`counters.json` 和 `flags.json` 的變更和其他變更一起顯示。
- **類型分頁：事件類型清單**，存在 `assets/data/events/kinds.json`（新；第一次編輯類型時
  建立，在那之前使用事件池今天用的七種類型）：

  ```json
  { "relic": { "name": { "zh_TW": "遺物", "en": "Relic" }, "color": "#e0b44c", "desc": { "en": "…" } } }
  ```

  每種類型一列：顏色、ID、名稱（zh_TW / en）、說明，以及有幾個事件使用它（點
  數字會篩選事件樹；點一個事件會開啟它）。**+ 新增類型** 會新增一種（任何名稱都可以，包括
  繁體中文；只有 `" ' < > & | \ /` 和頭尾空白不行）。改 ID 會把該類型的每個事件一起改名。**把事件移到
  另一種類型：** 在一列中勾選事件（或 **全選**），再在 *把選取的 N 個移到…* 中選類型；
  只有勾選的事件會移動，算一個復原步驟。事件上的 ↗ 會開啟它；很長的列只顯示 12 個事件
  和 *還有 N 個*。還在使用中的類型不能刪除：最後一個事件移走後，**刪除** 才會出現。
  有事件使用、但清單中沒有的類型，會有一個 ⚠ 列，附 *加入清單*，它的事件也可以
  用同樣的方式移動。屬性面板的類型下拉選單、類型篩選，以及兩個編輯器中的類型顏色都讀這份清單
  （`make_data.py` 和 `make_bundle.py` 會複製它）；下拉選單還有 *+ 新增類型…*，會開啟這個分頁。
  樓層的 `meta.eventKinds` 是樓層產生器留下的紀錄，不會被修改。遊戲還不會讀 `kind`：
  陷阱和補給的效果來自事件 ID 中的字（第 6 節第 6 項）。
- **檢查：**

| 檢查 | 嚴重度 |
|---|---|
| 事件的類型不在 `kinds.json` 中 | ⚠ |
| 條件、動作或觸發指名了不存在的變數、計數器、旗標、物品或事件 | ⛔ |
| `next` 連到沒有任何事件池定義的事件 | ⛔ |
| 沒有任何事件連結到的 `chain` 事件；NPC 沒有放在任何樓層上的 `talk` 事件 | ⚠ 永遠不會觸發 |
| `var ≥ N`，但沒有任何事件改變這個變數，且它的預設值低於 N | ⚠ 永遠不會啟用 |
| 透過 `next` 連回自己的事件 | ⚠ 迴圈 |
| 沒有任何東西讀寫的事件變數 | ⓘ |

觸發方式不是 `step` 的事件不需要樓層，所以不再被回報為孤立事件。

## 4. 儲存

有邏輯的紀錄會完整寫出；沒有邏輯的紀錄和今天一樣保持一行。第一次新增事件變數時，
會建立新的 `story/vars.json`。

## 5. 先做 HTML，再做 Qt

節點編輯器是純 HTML、CSS 和 SVG，沒有用任何函式庫。用 HTML 做並不難：
教學頁面中它已經能運作，播放示範還用真正的滑鼠事件操作它。至於 Qt/C++ 編輯器
（[19_STAGE_EDITOR.md](../19_STAGE_EDITOR.md) 第 6 節），imgui-node-editor 本身就很合適：它是
MIT 授權，需要 Dear ImGui 1.72+ 和 C++14，而引擎已經有 ImGui-on-bgfx 層
（`src/engine/src/imgui_bgfx.h`）。圖的模型和「這條連線代表什麼」的規則
（mockup 中的 `linkAction`）可以原封不動沿用。

## 6. 執行期的工作（第 2、7 項已於 2026-10-10 完成，其餘尚未）

   集合。
2. **每個事件都要有「事件完成」。** 今天 `game_input.cpp` 只為低語和救援設定 `event_<id>`；

3. `condition.cpp` 中的**條件葉節點** `varAtLeast` / `varEquals`（加上 context 方法）。
4. **動作** `addVar` / `setVar` / `setFlag`，放在現有的對話動作旁邊。
5. **分派器：** 在格子上、交談時（對話關閉之後）、變數改變時，以及透過
   `next` 觸發；檢查 `requires` 和 `once`；防止迴圈（每條鏈中一個事件最多觸發一次）。
6. **效果來自資料：** `game_input.cpp` 中寫死的「陷阱 = −8 HP，補給 = +10 HP +12 金幣」

7. **給玩家事件紀錄用的事件狀態**（§7）：每個事件的已開始／已完成，隨這輪遊戲存檔。

## 7. 玩家的事件紀錄

玩家選單的 **事件** 分頁（[20_PLAYER_MENU.md](../20_PLAYER_MENU.md) §6）列出玩家已開始或已完成的，從不列出還沒遇到的，
並可切換 **未完成** 和 **全部**。選中的項目只顯示它的 **標題**、**說明**，以及 **相關** 事件的名稱
（擁有者的規則，2026-10-10）。

### 標題和說明

每個事件都有這兩者，都是文字鍵（[01_DATA_MODEL.md](01_DATA_MODEL.md)）：

```json
{ "eventId": "ev_elder_thanks", "kind": "rescue", "text": "ev_elder_thanks.text",
  "title": "ev_elder_thanks.title", "desc": "ev_elder_thanks.desc" }
```

- `text` 不變：事件觸發時顯示的那一行。
- `title` 是紀錄中的名稱，`desc` 是下面的一段說明。兩者都必填：缺少它們，或鍵在 `text.json` 中不存在時，問題清單會回報。

### 哪些事件會列出

| 狀態 | 何時 | 列出 |
|---|---|---|
| **未知** | 以下皆非 | 否 |
| **已開始** | 玩家遇過它：走到它的格子、和它的 NPC 交談過，或它的某個 `requires` 條件成立了（例如兩條線索中的第一條） | **未完成** 和 **全部** |
| **已完成** | 它已觸發（這輪的已完成事件集合，§6 第 1–2 項） | 只在 **全部**，標記 ✓ |

「已開始」和已完成集合一起存在這輪遊戲中，所以存檔、讀檔後紀錄仍在。

一觸發就結束的小事件可以整個種類不進紀錄：`kinds.json` 每個種類加 `"inLog": false`（預設 `true`），
單一事件也可以用自己的 `"inLog"` 覆蓋。

### 相關事件

事件邏輯把兩個事件連在一起時（任一方向），它們就是相關事件：

| 連結 | 例子 |
|---|---|
| 這個事件的 `next` 指向另一個 | 救援之後接村長的謝意 |
| 這個事件的 `requires` 等另一個完成（`eventDone`） | 謝意等救援完成 |
| 另一個的 `next` 或 `requires` 指向這個 | 同樣的連結，從另一邊看 |

詳細內容以標題列出相關事件（已完成的有 ✓）。玩家還沒遇到的相關事件顯示為 **？？？**，避免紀錄劇透後面的內容。
章節的相關事件是它的劇情事件（種類為 `event` 的 `beats`）。

### 編輯器
