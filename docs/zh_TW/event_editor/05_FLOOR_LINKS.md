# 05 — 樓層連結：一層樓多座樓梯，由事件上鎖

> 英文原文：[05_FLOOR_LINKS.md](../../event_editor/05_FLOOR_LINKS.md)

**現況：** 設計，以及編輯器的 mockup（[tools/web_editors/event_editor.html](../../../tools/web_editors/event_editor.html)，第四部分）。
**遊戲自 2026-10-12 起會讀取這個格式**（第 5 節），並採用負責人對 Q7 的答覆：上鎖的樓梯看得見，上面有鎖頭（第 3.2 節）。
關卡編輯器還不能放置額外的樓梯格。

## 1. 改變了什麼

今天每層樓都剛好有一座上樓梯和一座下樓梯：

- 每個樓層設定都有 `"nextFloor": "F51"`，而 F01 → F02 → … → F70 這條鏈就是整張地圖；
- 遊戲把它複製到 `Stage::up` / `Stage::down`（`src/core/game/core/stage.h`、
  `game_assets.cpp`），每張地圖格有一個 `U` 和一個 `D` 格。

新的規則：

- **一層樓可以有任意數量的樓梯，往上或往下，通往任何樓層。** 例如 F50 往上可以到
  F51，*也可以*到 F96。
- **樓梯可以被事件鎖住。** F50 → F96 的樓梯會一直隱藏，直到玩家完成指定的事件，
  例如 `ev_common_relic_road`。之後它的樓梯格才會出現。

## 2. 資料格式

樓層設定多了一個 `stairs` 清單：

```json
// assets/data/story/floors/F50.json
{
  "id": "F50", "act": "ch_08", ...
  "nextFloor": "F51",
  "stairs": [
    { "dir": "up",   "to": "F51" },
    { "dir": "down", "to": "F49" },
    { "dir": "up",   "to": "F96", "unlock": { "eventDone": "ev_common_relic_road" } }
  ]
}
```

| 欄位 | 意義 |
|---|---|
| `dir` | `up` 或 `down`：用哪種樓梯格，以及從哪一側抵達 |
| `to` | 通往的樓層 ID。任何樓層、任何章節都可以，包括 F70 之後的樓層，例如 F96 |
| `unlock.eventDone` | 選填。在本局完成這個事件之前，樓梯都是隱藏的 |

**相容性。** 沒有 `stairs` 清單的樓層維持今天的行為：往上到它的 `nextFloor`，
往下到 `nextFloor` 是本層的那一層。所以現有的 70 層樓不需要改，編輯器也只會
把 `stairs` 清單寫進你編輯過的樓層。`nextFloor` 會留在檔案中給舊版遊戲用；兩者都存在時，
以 `stairs` 為準。

**新樓層** 就只是一個新的設定檔。F96 可以屬於任何章節（編輯器會複製建立它的那層樓的
章節）。它的地圖格 `F96.stage.json` 和其他樓層一樣，由設定產生。

## 3. 遊戲的規則（實作後）

1. **事件完成** 指玩家在本局完成了那個事件：也就是今天它的格子被清除的那一刻
   （`game_input.cpp` 的 `event:` 分支）。這一局會保存一組已完成的事件 ID，
   和這局的其他資料一起存檔，開新遊戲時重置。
2. **看得見，有鎖頭（負責人對 Q7 的答覆，2026-10-12；最初的設計是隱藏）。**
   - 上鎖的樓梯畫得較暗，上面有鎖頭。走進去不會上下樓，而是出現一行提示：
     *These stairs are locked. Finish "…" to open them.* 玩家還沒遇過那個事件時，名稱顯示為「???」，與事件紀錄相同。
   - 事件完成時跳出對話框，指出是哪座樓梯：*Stairs unlocked — The stairs on floor 3 that lead to floor 4 are
     now open.* 玩家若在那層，鎖頭立刻消失。
   - 解鎖事件在事件紀錄裡的說明，結尾會加上 *Finishing it opens the stairs on floor 3 to floor 4.*
   - 同時開始一個後續事件 **「Go to the stairs on floor 3」**，說明為 *The stairs on floor 3 that lead to floor 4
     are open. Go there and take them.*，玩家走過那座樓梯時完成。它的 id 是 `stairs_<樓層>_<目的地>`，
     由遊戲依樓層規格產生，不需要事件池紀錄。
3. **抵達。** 從 A 經樓梯到 B，會落在 B 上通往 A 的那座樓梯。如果 B
   沒有這樣的樓梯（單向連結），玩家會落在 B 第一座方向相反的樓梯，或落在
   `player_start`。
4. **解鎖事件必須能出現。** 樓層的 `events` 清單是它*能*抽到的事件；
   產生器必須一定放置某座樓梯在等待的事件，否則那座樓梯永遠打不開。
5. **地圖格。** 每座樓梯都需要自己的格子。圖例給每座樓梯一個字母，例如
   `"U": "stairs_up:F51"`、`"V": "stairs_up:F96"`、`"D": "stairs_down:F49"`。產生器為
   `stairs` 中每一項放一個格子。

## 4. 編輯器檢查什麼

| 規則 | 嚴重度 | 意義 |
|---|---|---|
| 缺少的樓層 | ⛔ 錯誤 | 樓梯通往一個沒有設定檔的樓層 ID。修正：**建立樓層**（或改樓梯的目標） |
| 未知的解鎖事件 | ⛔ 錯誤 | `unlock.eventDone` 指名的 ID 沒有任何事件池定義 |
| 無法到達的樓層 | ⚠ 警告 | 從 F01 出發，經由開放的樓梯，或經由「事件能在先前到達的樓層抽到」的上鎖樓梯，都到不了這層樓。能抓出只在另一側、或根本不在任何樓層的解鎖事件 |

可到達性檢查從 F01 開始。它沿著開放的樓梯走；當某個已到達的樓層能抽到上鎖樓梯的事件時，
也會走那座上鎖樓梯。重複直到沒有新的樓層可到達為止。

在 mockup 中：

- **樓層圖**（下方分頁）：每章一列，每座樓梯一個箭頭。上鎖的樓梯是金色
  虛線，標上 🔒 和它的事件。通往缺少樓層的樓梯會終止於紅色的 ⛔ 替身。
  無法到達的樓層有橘色虛線外框。
- **樓層屬性面板**（點一層樓）：章節、樓梯表（方向、目標、*完成後解鎖*、✕）、
  **+ 新增樓梯**、*從哪裡到達*，以及它能抽到的事件。
- **儲存** 會把 `stairs` 清單寫進每個編輯過的樓層，新樓層則寫成新檔案。
