# 19 — 關卡編輯器（現在是 HTML，接下來是 Qt + 遊戲引擎）

> 英文原文：[19_STAGE_EDITOR.md](../19_STAGE_EDITOR.md)

**現況：** HTML 編輯器可以用了：`tools/web_editors/stage_editor.html`，和事件編輯器放在一起（開啟
`tools/web_editors/index.html`，用 **⇄** 按鈕切換）。第 6 節規劃
Qt/C++ 版本，它會用遊戲自己的渲染器繪製，所以編輯器顯示的就是遊戲
顯示的。

關卡編輯器繪製樓層的地圖格：牆、樓梯、門、鑰匙、怪物、NPC、物品、玩家
起點，以及**事件物件**。它讀寫的就是遊戲載入的那些檔案：

| 檔案 | 編輯器修改的內容 |
|---|---|
| `assets/data/story/floors/F??.stage.json` | `tiles`（每格一個字元）、`legend`、`name`、`connect`、`width` / `height` |
| `assets/data/stages/stageNN.json` | 同上，給十個手工製作的頭目關卡（樓層設定中的 `handAuthoredStage`） |
| `assets/data/story/floors/F??.json` | `events`：放置事件會把它加進樓層的清單，讓樓層能抽到它 |

## 1. 執行

| 方式 | 能用的功能 |
|---|---|
| 雙擊 `stage_editor.html` | 除了寫入磁碟之外都可以。它載入 `stage_bundle.js` 中的副本；**儲存 → 下載檔案**：只有一個檔案變更時直接下載該檔案；多個檔案時下載成 **一個 zip**（`toms_stage_changes_<日期>_<時間>.zip`），保留每個檔案的 `assets/data/...` 路徑。在 TOMS 資料夾中解壓縮並取代原檔即可 |
| `tools\web_editors\serve.cmd`，然後 **開啟專案資料夾…** 並選 TOMS 資料夾（Chrome 或 Edge） | 讀取實際的檔案，**儲存** 會就地寫入。每個檔案會先備份到 `Build/editor_backups/<日期-時間>/`。事件編輯器會自動開啟同一個資料夾（兩個編輯器都可以開），兩個編輯器都改過的樓層 `events` 清單會保留兩邊的變更 |

`serve.cmd` 會先更新兩個編輯器的資料副本（它執行 `make_data.py` 和 `make_bundle.py`），
所以編輯器開啟時永遠是目前的 `assets/data`。不用伺服器時，資料改變後請執行
`tools/web_editors/refresh_data.cmd`。

**大小。** 所有東西都可以放大：

| 什麼 | 怎麼做 |
|---|---|
| 介面（文字、按鈕、面板） | 上方列的 🔍 清單，或 **Alt + =** 放大、**Alt + -** 縮小、**Alt + 0** 回到預設。瀏覽器會記住選擇 |
| 地圖縮放 | **在地圖上捲動滑鼠滾輪** 以游標為中心放大縮小（滑鼠下的格子保持不動）；縮放百分比旁的 **+** / **−**，以及 **+** / **-** 鍵也可以 |
| 地圖平移 | **右鍵拖曳**（右鍵點一下不移動仍是取色器）、**中鍵拖曳**，或按住 **Space** 拖曳；**Shift + 滾輪** 左右捲動；捲軸。視圖可以平移到地圖邊緣之外 |
| 預設值 | [`tools/web_editors/settings.js`](../../tools/web_editors/settings.js)：`uiScale`（1.25 = 125%）、`mapZoom`（2 = 64 px 的格子）、`language`。編輯、儲存，按 F5 |

在編輯器中選的大小會優先於 `settings.js`，直到按 **Alt + 0**（或在 🔍 清單中選 *settings.js*）。
瀏覽器自己的縮放（**Ctrl + =** / **Ctrl + -**）也可以用。

## 2. 使用方式

- **樓層：** 從清單中選，或按 `[` / `]`。● 標示有未儲存變更的樓層，★
  標示手工製作的頭目關卡。
- **調色盤：** 地形、樓梯、玩家起點、門、鑰匙、怪物、NPC、物品，用遊戲的
  sprite（`assets/media/sprites`）繪製。小字母是這個樓層用來代表它的字元。
- **事件：** 左側的清單。*這個樓層可抽到的* 排在最前面（✓ n = 放了 n 次），然後是
  各事件池的所有事件。搜尋會比對 ID、類型和文字。放置的事件看起來像遊戲的劇情板
  （金色帶石板色內嵌），再加上一個類型顏色的圓點。紅點表示沒有事件池定義它。
- **工具：** 🖌 繪製（B）、▭ 矩形（R）、⌫ 擦除（E）、↖ 選取 / 移動（V：拖曳物件來移動
  它）。右鍵點一下（不拖曳）會把游標下的格子當作筆刷；右鍵拖曳平移視圖。格線（G）、縮放（+ / −）、復原 / 重做
  （Ctrl+Z / Ctrl+Y）、儲存（Ctrl+S），Delete 清除選取的格子。
- **物件需要空的地板。** 怪物、NPC、物品、鑰匙、門、樓梯、事件和玩家起點
  只能放在空的地板上，大型怪物（golem 和 demon 2×1，Vorkath 2×2）需要它佔地的每一格
  都是空的。物件筆刷停在地圖上時，預覽會跟著游標：放得下的地方是綠色外框，
  被牆、其他物件（包括大型怪物的額外格子）或地圖邊緣擋住的地方是紅色。
  紅色的格子不會被繪製，矩形工具會略過它們（*略過 N 格*），拖曳移動到那裡會被
  拒絕，狀態列會說明是什麼擋住了。牆和地板仍然可以蓋過任何東西；要取代某個物件，
  請先擦除或移走它。
- **屬性面板：** 選取的格子：它的物件和圖例字元、怪物的 HP / ATK / DEF 和大小、
  物品的效果，或事件的類型、事件池、文字（zh_TW 和 en），以及能抽到它的樓層，附
  *取代為*。下方：樓層的名稱、`connect.up` / `connect.down`、大小，以及它的事件清單。
- **檢查**（下方），點一項就會標出它的格子：

| 檢查 | 嚴重度 |
|---|---|
| 某個字元沒有圖例項目 | ⛔ |
| 放置了沒有任何事件池定義的事件 | ⛔ |
| 沒有樓梯也沒有 `@`：玩家會出現在 (1, height − 2) | ⛔ |
| 放置了事件，但它不在樓層的 `events` 清單中（修正：*加入清單*） | ⚠ |
| 同一個事件放了兩次（一層樓不應該重複同一個事件） | ⚠ |
| 設定了 `connect.up` 但沒有 `U` 格，或有 `U` 格但沒有 `connect.up`（下樓同理） | ⚠ |
| 從玩家抵達的位置無法到達的物件（牆會擋住；門和怪物可以通過） | ⚠（地圖上的橘色虛線外框） |
| 2 格寬或 2 格高的怪物旁邊沒有空格 | ⚠ |
| 在 `events` 清單中但沒有放置的事件；外緣有開口的格子 | ⓘ |

## 2b. 放置事件：手動、從事件編輯器，或自動

**從事件編輯器。** *+ 新增樓層…* 有 *接著開啟關卡編輯器把它放到地圖上*（預設
開啟），每個樓層標籤也都有一個 📍 按鈕。兩者都會以
`?floor=F02&floors=F02,F04&place=<eventId>&kind=<kind>` 開啟這個編輯器：樓層已開啟，事件就是筆刷，
安全的格子會染成綠色，並有一條提供 **建議一格**、**幫我放** 和 **下一個：F04 ▶** 的列。
目前只存在於事件編輯器中的事件也一樣會被放置，並標示為還沒存進
事件池。

**劇情檢查（下方分頁 *劇情 · 所有樓層*）。** 它依攀爬順序走過各樓層（從 F01 開始的 `nextFloor`），
套用遊戲的規則：`y` / `b` / `r` 門要消耗一把同色鑰匙，碰到鑰匙就撿起來，`U` / `D` 結束這層樓。
開門的每一種順序都會嘗試，所以檢查是精確的
（怪物視為可以打倒）。每層樓會顯示帶進來的鑰匙、這層樓上的鑰匙、
最少開門的上樓路線上的門，以及玩家最多能帶出去的鑰匙。它回報：

| 問題 | 嚴重度 |
|---|---|
| 上樓的路需要某種顏色的鑰匙，比帶進來的加上找到的還多，例如 *需要 3 把黃鑰匙；帶進 0 把 + 這層 0 把* | ⛔ |
| 上樓梯被牆圍住了 | ⛔ |
| 某個事件需要的鑰匙在這層樓之前拿不到，或被牆圍住了 | ⛔ |
| 某個事件在不屬於上樓路線的門後面：在那裡花掉鑰匙，可能會讓上樓的路不夠用 | ⚠ |
| 某個事件需要另一個事件完成（`requires`），而那個事件最早出現在更後面的樓層，或根本不出現 | ⚠ |
| 某個事件需要 `var ≥ N`，但到它所在樓層為止的事件只能達到更少 | ⚠ |
| 上鎖的樓梯（[05](event_editor/05_FLOOR_LINKS.md)）等待的事件在它的樓層之前無法完成 | ⛔ |

交談事件從它的 NPC 所在的樓層算起；連結和變數觸發的事件從
觸發它的東西所在的樓層算起。以今天的資料，檢查沒有發現任何阻擋：每個產生的樓層都有一把黃
鑰匙，而在上樓的路需要開門的地方（F05、F06、…），到那時找到的鑰匙都夠用。
把 F01–F05 的黃鑰匙拿掉，就能看出它的用途：F03 和 F05 會變成 ⛔ *需要 1 把黃鑰匙；帶進
0 把 + 這層 0 把*。

**🎲 自動放置事件…** 把每層樓 `events` 清單中的事件放到地圖上，可以只做這層樓，或一鍵做
所有樓層：
- 只放在**安全的格子**上：在最少開門的上樓路線上可到達的空地板（最頂層：不經過任何門），
  絕不緊鄰樓梯、門或起點，所以事件永遠不會耗掉上樓需要的鑰匙；
- 分散開來（盡可能遠離其他物件，房間優先於走廊），並使用種子：同樣的種子
  得到同樣的格子，🎲 換一個；
- 只處理踩到格子才觸發的事件（交談 / 連結 / 變數事件不需要格子）；沒有事件池
  定義的 ID 會被排除並回報；
- *只處理還沒放置的事件*，或 *把每個事件移到新的格子*。

每層樓算一個復原步驟，每個放置的事件都可以和其他東西一樣被移動或擦除，儲存時會先顯示
變更再寫入。◇ **安全格子** 隨時顯示同樣的格子。

## 3. 編輯器遵守的資料規則

- **門和樓梯保留它們的字元。** 遊戲直接讀取 `y` `b` `r` `U` `D`（`movePlayer`、
  `walkPassable`），不透過圖例，所以編輯器一律給門或樓梯那個字元（如果有其他東西
  用了它就把那個東西換掉），並標出把它們對應到別的東西的檔案。

- **字元是每個檔案各自的。** 放置東西時，會沿用檔案中已有的對應字元，否則用它慣用的
  字元（`1` 史萊姆、`y` 黃門、…），再不然就用一個空的字元（`E F G I J …`，和產生器一樣）。
  儲存時，本次新增、但沒有任何格子使用的字元會被丟掉；檔案原本就有的圖例項目會保留。
- **玩家抵達的位置**，依遊戲的順序：下樓梯，否則 `@`，否則上樓梯。
  產生的樓層沒有 `@`。
- **檔案以遊戲工具的方式寫出：** 2 格縮排的 JSON、相同的鍵順序，以及檔案
  自己的換行字元（頭目關卡用 CRLF）。開啟樓層後沒有編輯就儲存，不會寫入任何東西。
- **產生的地圖格：** `F??.stage.json` 由樓層產生器產生。再執行一次會
  取代手動的編輯；被手動編輯過的樓層應該改成手工製作，或讓產生器
  保留它的編輯。這需要做決定。

## 4. 製作過程中發現的事

- **遊戲會忽略 `@`。** `parseStage` 會略過 `@` 格（`stage.h`，`c == '@'` → `continue`），
  所以 `game_assets.cpp` 抵達程式碼中的 `@` 分支永遠找不到它。在 F01 開新遊戲時是從
  F01 的樓梯開始，而不是它的 `@`。修正只要一行；這裡沒有改。
- 在全部 70 層樓中，檢查回報了 324 個放置了、但沒有事件池定義的事件（
  [event_editor/01_DATA_MODEL.md](event_editor/01_DATA_MODEL.md) 中第 4–10 章的 ID）、75 個列出了但
  沒有放置的事件，以及一層有下樓梯格但沒有 `connect.down` 的樓層。

## 5. HTML 編輯器還沒有的功能

- 一層樓多座樓梯，以及由事件上鎖的樓梯（[event_editor/05_FLOOR_LINKS.md](event_editor/05_FLOOR_LINKS.md)）：
  地圖格那一側（`"V": "stairs_up:F96"`）要等執行期的工作完成。
- 每格的 `footprints` 和 `encounter_overrides`：會顯示並遵守，但不能編輯。
- 試玩：用遊戲的規則在樓層上走動。那屬於 Qt 版本（第 6 節）。

## 6. 計畫：遊戲引擎上的 Qt / C++ 編輯器

目標：**編輯器顯示的就是遊戲運作的方式。** 相同的渲染器、相同的規則，而且
能在編輯器中直接玩這層樓。

| 部分 | 怎麼做 |
|---|---|
| 視窗 | `toms_editor`（Qt6 Widgets）中的 **Stage** 分頁，取代舊的 `src/editor/stage` 編輯器，配置和這個 HTML 版本一樣 |
| Viewport | `bgfx_viewport`（已經內嵌遊戲的 bgfx 視圖）用 toms_game 的 `BgfxRenderer` 繪製樓層：相同的 atlas、每一幕的色調（`floorThemeTint`）、佔地，以及事件板 |
| 模型 | 一個和遊戲共用的 C++ 關卡模型：用 `parseStage` 載入，加上一個遵守第 3 節格式規則的寫入器。沒有第二個解析器 |
| 編輯 | 在 viewport 上繪製 / 矩形 / 擦除 / 移動；調色盤、事件清單、屬性面板和檢查做成 Qt 停駐面板；`QUndoStack` 加上歷程面板和自動備份，和動畫、粒子編輯器一樣 |
| 檢查 | 同樣的檢查，移到一個不依賴 Qt 的小型 C++ 函式庫（像 `event_graph`），附無介面測試，讓 CI 能檢查每層樓 |
| 試玩 | **▶ 從這裡開始玩**：在 viewport 中對編輯中的樓層執行真正的 `Game`，玩家的能力值和鑰匙在側邊面板設定；**■** 回到編輯，樓層不變 |
| 連結 | 點一個事件會在事件編輯器中開啟它；樓梯會顯示並可編輯它的目標樓層（之後還有 05 的 `stairs` 清單） |

階段：(1) 用遊戲渲染器的唯讀 viewport；(2) 繪製、儲存和復原；(3) 檢查
函式庫和測試；(4) 從這裡開始玩；(5) 執行期支援之後的多樓梯樓層。
