# 19 — 關卡編輯器（HTML 版，以及遊戲引擎上的 Windows 程式）

> 英文原文：[19_STAGE_EDITOR.md](../19_STAGE_EDITOR.md)

**現況：** 兩個編輯器，讀寫相同的檔案。

- **HTML 版：** `tools/web_editors/stage_editor.html`，和事件編輯器放在一起（開啟
  `tools/web_editors/index.html`，用 **⇄** 按鈕切換）。
- **Windows 程式（2026-10-16）：** `stage_event_editor.exe`（第 6 節）。它用 Qt、C++ 和遊戲的 bgfx 渲染器，
  所以地圖的畫法和遊戲完全一樣，連動畫也是。兩個編輯器都是原生的：關卡編輯器（第 1 階段）和事件編輯器（第 2 階段）。

關卡編輯器繪製樓層的地圖格：牆、樓梯、門、鑰匙、怪物、NPC、物品、玩家
起點，以及**事件物件**。它讀寫的就是遊戲載入的那些檔案：

| 檔案 | 編輯器修改的內容 |
|---|---|
| `assets/data/story/floors/F??.stage.json` | `tiles`（每格一個字元）、`legend`、`name`、`connect`、`width` / `height` |
| `assets/data/stages/stageNN.json` | 同上，給十個手工製作的頭目關卡（樓層設定中的 `handAuthoredStage`） |
| `assets/data/story/floors/F??.json` | `events`：放置事件會把它加進樓層的清單，讓樓層能抽到它 |

## 1. 執行

| 方式 | 能用的功能 |
|---|---|
| 雙擊 `stage_editor.html` | 除了寫入磁碟之外都可以。它載入 `stage_bundle.js` 中的副本；**儲存 → 下載檔案**：只有一個檔案變更時直接下載該檔案；多個檔案時下載成 **一個 zip**（`toms_stage_changes_<日期>_<時間>.zip`），保留每個檔案的 `assets/data/...` 路徑。在 TOMS 資料夾中解壓縮並取代原檔即可 |
| `tools\web_editors\serve.cmd`，然後 **開啟專案資料夾…** 並選 TOMS 資料夾（Chrome 或 Edge） | 讀取實際的檔案，**儲存** 會就地寫入。每個檔案會先備份到 `Build/editor_backups/<日期-時間>/`。事件編輯器會自動開啟同一個資料夾（兩個編輯器都可以開），兩個編輯器都改過的樓層 `events` 清單會保留兩邊的變更 |

`serve.cmd` 會先更新兩個編輯器的資料副本（它執行 `make_data.py` 和 `make_bundle.py`），
所以編輯器開啟時永遠是目前的 `assets/data`。不用伺服器時，資料改變後請執行
`tools/web_editors/refresh_data.cmd`。

**大小。** 所有東西都可以放大：

| 什麼 | 怎麼做 |
|---|---|
| 介面（文字、按鈕、面板） | 上方列的 🔍 清單，或 **Alt + =** 放大、**Alt + -** 縮小、**Alt + 0** 回到預設。瀏覽器會記住選擇 |
| 地圖縮放 | **在地圖上捲動滑鼠滾輪** 以游標為中心放大縮小（滑鼠下的格子保持不動）；縮放百分比旁的 **+** / **−**，以及 **+** / **-** 鍵也可以 |
| 地圖平移 | **右鍵拖曳**（右鍵點一下不移動仍是取色器）、**中鍵拖曳**，或按住 **Space** 拖曳；**Shift + 滾輪** 左右捲動；捲軸。視圖可以平移到地圖邊緣之外 |
| 面板 | 拖曳兩個面板之間的邊線：物件 / 事件欄、屬性面板、地圖下方的檢查，以及物件與事件清單之間的線。大小由瀏覽器記住；在邊線上 **按兩下** 恢復預設（`tools/web_editors/splitter.js`） |
| 預設值 | [`tools/web_editors/settings.js`](../../tools/web_editors/settings.js)：`uiScale`（1.25 = 125%）、`mapZoom`（2 = 64 px 的格子）、`language`。編輯、儲存，按 F5 |

在編輯器中選的大小會優先於 `settings.js`，直到按 **Alt + 0**（或在 🔍 清單中選 *settings.js*）。
瀏覽器自己的縮放（**Ctrl + =** / **Ctrl + -**）也可以用。

## 2. 使用方式

- **樓層：** 從清單中選，或按 `[` / `]`。● 標示有未儲存變更的樓層，★
  標示手工製作的頭目關卡。
- **調色盤：** 地形、樓梯、玩家起點、門、鑰匙、怪物、NPC、物品，用遊戲的
  sprite（`art_raw/sprites`）繪製。小字母是這個樓層用來代表它的字元。
- **事件：** 左側的清單。*這個樓層可抽到的* 排在最前面（✓ n = 放了 n 次），然後是
  各事件池的所有事件。搜尋會比對 ID、類型和文字。放置的事件看起來像遊戲的劇情板
  （金色帶石板色內嵌），再加上一個類型顏色的圓點。紅點表示沒有事件池定義它。
- **工具：** 🖌 繪製（B）、▭ 矩形（R）、⌫ 擦除（E）、↖ 選取 / 移動（V：拖曳物件來移動
  它）。右鍵點一下（不拖曳）會把游標下的格子當作筆刷；右鍵拖曳平移視圖。格線（G）、縮放（+ / −）、復原 / 重做
  （Ctrl+Z / Ctrl+Y）、儲存（Ctrl+S），Delete 清除選取的格子。
- **物件需要空的地板。** 怪物、NPC、物品、鑰匙、門、樓梯、事件和玩家起點
  只能放在空的地板上，大型怪物（golem 和 demon 2×1，Vorkath 2×2）需要它佔地的每一格
  都是空的。物件筆刷停在地圖上時，預覽會跟著游標：放得下的地方是綠色外框，
  被牆、其他物件（包括大型怪物的額外格子）或地圖邊緣擋住的地方是紅色。
  紅色的格子不會被繪製，矩形工具會略過它們（*略過 N 格*），拖曳移動到那裡會被
  拒絕，狀態列會說明是什麼擋住了。牆和地板仍然可以蓋過任何東西；要取代某個物件，
  請先擦除或移走它。
- **屬性面板：** 選取的格子：它的物件和圖例字元、怪物的 HP / ATK / DEF 和大小、
  物品的效果，或事件的類型、事件池、文字（zh_TW 和 en），以及能抽到它的樓層，附
  *取代為*。下方：樓層的名稱、`connect.up` / `connect.down`、大小，以及它的事件清單。
- **NPC 面板**（在地圖上點一個 NPC；[event_editor/08](event_editor/08_NPC_DIALOGUE.md)）：它的名字、閒聊台詞的數量（沒有 NPC 檔時 ⚠），
  以及依遊戲選單順序排列的話題，每個標示 *在它所在的每一層*、*只在這一層* 或 *只在 F07*（不在這一層時變淡），並標示 *有條件*、
  ✓ *完成後對話* 與 ↻（可重複）。↗ 在事件編輯器中開啟該話題；**在事件編輯器中編輯 →** 開啟該 NPC 的 NPC 分頁。
  開啟專案資料夾時，面板會跟著事件編輯器儲存的內容更新。
- **檢查**（下方），點一項就會標出它的格子：

| 檢查 | 嚴重度 |
|---|---|
| 某個字元沒有圖例項目 | ⛔ |
| 放置了沒有任何事件池定義的事件 | ⛔ |
| 沒有樓梯也沒有 `@`：玩家會出現在 (1, height − 2) | ⛔ |
| 放置了事件，但它不在樓層的 `events` 清單中（修正：*加入清單*） | ⚠ |
| 同一個事件放了兩次（一層樓不應該重複同一個事件） | ⚠ |
| 設定了 `connect.up` 但沒有 `U` 格，或有 `U` 格但沒有 `connect.up`（下樓同理） | ⚠ |
| 從玩家抵達的位置無法到達的物件（牆會擋住；門和怪物可以通過） | ⚠（地圖上的橘色虛線外框） |
| 2 格寬或 2 格高的怪物旁邊沒有空格 | ⚠ |
| 在 `events` 清單中但沒有放置的事件；外緣有開口的格子 | ⓘ |

## 2b. 放置事件：手動、從事件編輯器，或自動

**從事件編輯器。** *+ 新增樓層…* 有 *接著開啟關卡編輯器把它放到地圖上*（預設
開啟），每個樓層標籤也都有一個 📍 按鈕。兩者都會以
`?floor=F02&floors=F02,F04&place=<eventId>&kind=<kind>` 開啟這個編輯器：樓層已開啟，事件就是筆刷，
安全的格子會染成綠色，並有一條提供 **建議一格**、**幫我放** 和 **下一個：F04 ▶** 的列。
目前只存在於事件編輯器中的事件也一樣會被放置，並標示為還沒存進
事件池。

**劇情檢查（下方分頁 *劇情 · 所有樓層*）。** 它依攀爬順序走過各樓層（從 F01 開始的 `nextFloor`），
套用遊戲的規則：`y` / `b` / `r` 門要消耗一把同色鑰匙，碰到鑰匙就撿起來，`U` / `D` 結束這層樓。
開門的每一種順序都會嘗試，所以檢查是精確的
（怪物視為可以打倒）。每層樓會顯示帶進來的鑰匙、這層樓上的鑰匙、
最少開門的上樓路線上的門，以及玩家最多能帶出去的鑰匙。它回報：

| 問題 | 嚴重度 |
|---|---|
| 上樓的路需要某種顏色的鑰匙，比帶進來的加上找到的還多，例如 *需要 3 把黃鑰匙；帶進 0 把 + 這層 0 把* | ⛔ |
| 上樓梯被牆圍住了 | ⛔ |
| 某個事件需要的鑰匙在這層樓之前拿不到，或被牆圍住了 | ⛔ |
| 某個事件在不屬於上樓路線的門後面：在那裡花掉鑰匙，可能會讓上樓的路不夠用 | ⚠ |
| 某個事件需要另一個事件完成（`requires`），而那個事件最早出現在更後面的樓層，或根本不出現 | ⚠ |
| 某個事件需要 `var ≥ N`，但到它所在樓層為止的事件只能達到更少 | ⚠ |
| 上鎖的樓梯（[05](event_editor/05_FLOOR_LINKS.md)）等待的事件在它的樓層之前無法完成 | ⛔ |

交談事件從它的 NPC 所在的樓層算起；連結和變數觸發的事件從
觸發它的東西所在的樓層算起。以今天的資料，檢查沒有發現任何阻擋：每個產生的樓層都有一把黃
鑰匙，而在上樓的路需要開門的地方（F05、F06、…），到那時找到的鑰匙都夠用。
把 F01–F05 的黃鑰匙拿掉，就能看出它的用途：F03 和 F05 會變成 ⛔ *需要 1 把黃鑰匙；帶進
0 把 + 這層 0 把*。

**🎲 自動放置事件…** 把每層樓 `events` 清單中的事件放到地圖上，可以只做這層樓，或一鍵做
所有樓層：
- 只放在**安全的格子**上：在最少開門的上樓路線上可到達的空地板（最頂層：不經過任何門），
  絕不緊鄰樓梯、門或起點，所以事件永遠不會耗掉上樓需要的鑰匙；
- 分散開來（盡可能遠離其他物件，房間優先於走廊），並使用種子：同樣的種子
  得到同樣的格子，🎲 換一個；
- 只處理踩到格子才觸發的事件（交談 / 連結 / 變數事件不需要格子）；沒有事件池
  定義的 ID 會被排除並回報；
- *只處理還沒放置的事件*，或 *把每個事件移到新的格子*。

每層樓算一個復原步驟，每個放置的事件都可以和其他東西一樣被移動或擦除，儲存時會先顯示
變更再寫入。◇ **安全格子** 隨時顯示同樣的格子。

## 2c. 類型、物件與遊戲畫面（2026-10-16）

**物件類型。** 調色盤中的怪物、道具或 NPC 是一個 *類型*：它在 `assets/data/enemies.json`、`assets/data/items.json` 或
`assets/data/npcs/<id>.json` 中的紀錄。
- 在調色盤項目上 **按兩下**（或屬性面板的 **類型詳細資料**）開啟它的視窗：
  - **外觀**：預設的精靈圖（列出所有精靈圖，可搜尋）、動畫（`assets/media/anim/*.anim` 中的任何片段），以及染色與不透明度；
  - **資料**：怪物的名字、生命、攻擊、防禦、經驗與金幣；道具的名字、描述、類型、價格、「重要」與效果（數值列）；NPC 的名字與招呼語
    （它的閒聊台詞與話題在事件編輯器的 NPC 分頁）。
- 怪物、道具或 NPC 群組上的 **+** 新增一個類型，從現有的複製（新的 NPC 也會得到一頁待改寫的對話）。**刪除這個類型** 只有在沒有樓層放置它時可用。
- 類型的精靈圖是紀錄的 `"sprite"`；動畫與染色放在 `"look"`：`{ "anim": "anim/<檔案>.anim#<片段>", "tint": [r, g, b, a] }`。
  染色會乘上精靈圖的顏色（白色 = 不變）。

**✎ 編輯（O）：單一放置物件自己的設定。** 在地圖上點一個物件；它的視窗有兩個分頁：
- **外觀**：它自己的精靈圖 / 動畫 / 染色（空白 = 使用類型的）；
- **事件**：連結或取消連結事件 id。玩家與該物件互動時觸發連結的事件：打敗怪物、撿起道具、打開門或專屬鑰匙門、與 NPC 交談、踩到事件格子。
  交談事件會成為該 NPC 的話題；其他事件在條件成立時執行（以通知顯示標題），否則標示為已開始。

它們以格子為鍵存在樓層的關卡檔中，移動物件時一起移動（擦除或被覆蓋時一起移除）：

```json
"objects": { "9,4": { "look": { "sprite": "npc_king", "tint": [1, 1, 1, 0.5] }, "events": ["ev_common_relic_road"] } }
```

在地圖上，有設定的物件會顯示 ✎（自己的外觀）、▶（動畫）與 ⚡n（連結的事件）。檢查會回報空格子上的設定（⚠）與沒有事件池定義的連結事件（⛔）。

**🎮 遊戲畫面（P）** 以遊戲的方式繪製樓層：所有外觀與染色，不顯示格線、標記、字元、可達性外框或選取。工具仍可使用。動畫在這裡顯示它的精靈圖
（遊戲中會播放）；在樓層上執行真正的遊戲是之後的計畫。

**儲存：** 樓層，以及變更的類型紀錄（`enemies.json`、`items.json`、`npcs/*.json`、新 NPC 的對話）。存在 `text.json` 的名字（道具、NPC）
與刪除的類型檔，只有在開啟專案資料夾時才會寫入。

**在遊戲中：** `Game::lookOf`（物件的外觀覆蓋類型的）、`drawObjectAnim`（任何片段，染色，依物件錯開時間）、`fireLinkedEvents`；由
`unit.talk_system_test`（資料中所有外觀與物件設定）與 `smoke.stage_objects`（`tests/stage/objects.stage.json`：染色的史萊姆、播放其他片段的蝙蝠、
以其他精靈圖繪製的村民、撿起時觸發連結事件的藥水）檢查。`toms_game --goto=<.json 的路徑>` 可直接開啟關卡檔（測試用）。

## 3. 編輯器遵守的資料規則

- **門和樓梯保留它們的字元。** 遊戲直接讀取 `y` `b` `r` `U` `D`（`movePlayer`、
  `walkPassable`），不透過圖例，所以編輯器一律給門或樓梯那個字元（如果有其他東西
  用了它就把那個東西換掉），並標出把它們對應到別的東西的檔案。

- **字元是每個檔案各自的。** 放置東西時，會沿用檔案中已有的對應字元，否則用它慣用的
  字元（`1` 史萊姆、`y` 黃門、…），再不然就用一個空的字元（`E F G I J …`，和產生器一樣）。
  儲存時，本次新增、但沒有任何格子使用的字元會被丟掉；檔案原本就有的圖例項目會保留。
- **玩家抵達的位置**，依遊戲的順序：下樓梯，否則 `@`，否則上樓梯。
  產生的樓層沒有 `@`。
- **檔案以遊戲工具的方式寫出：** 2 格縮排的 JSON、相同的鍵順序，以及檔案
  自己的換行字元（頭目關卡用 CRLF）。開啟樓層後沒有編輯就儲存，不會寫入任何東西。
- **樓層現在以手動編輯（2026-10-12）。** 70 層的 `F??.stage.json` 與樓層規格最初由樓層產生器產生。為了負責人對 Q6 的答覆，
  它曾被還原，並在取代手動編輯過的樓層前跳出對話框列出它們。**之後負責人決定只用本編輯器編輯樓層，所以產生器又被移除**
  （`tools/gen_floors.py`、`gen_stairs.py`、`maze_lib.py`、`floor_guard.py`；仍保留在 git 歷史中）。不會再有東西在背後改寫樓層。
  日後若要自動產生大量樓層，可從 git 還原。
- **每次儲存都會更新事件索引。** 本編輯器開啟專案資料夾時，以及每次存進資料夾後，都會重建
  `assets/data/events/floor_index.json`（`tools/web_editors/floor_index.js`；事件編輯器也一樣）。只有內容改變時才寫入。

## 5. HTML 編輯器還沒有的功能

- 一層樓多座樓梯，以及由事件上鎖的樓梯（[event_editor/05_FLOOR_LINKS.md](event_editor/05_FLOOR_LINKS.md)）：
  地圖格那一側（`"V": "stairs_up:F96"`）要等執行期的工作完成。
- 每格的 `footprints` 和 `encounter_overrides`：會顯示並遵守，但不能編輯。
- 試玩：用遊戲的規則在樓層上走動。那屬於 Qt 版本（第 6 節）。

## 6. Windows 程式：`stage_event_editor`（Qt / C++ / bgfx）

關卡編輯器和事件編輯器合成一個 Windows 程式，用遊戲自己的技術（Qt 6、C++、遊戲的 bgfx 渲染器），
沒有其他函式庫。**編輯器顯示的，就是遊戲運作的樣子。**

**執行：** `Editor\StageEventEditor.cmd`，或 `Build\windows-releasein\stage_event_editor.exe`。它從自己的資料夾
往上找 TOMS 資料夾（或用 `--root=<資料夾>`），直接處理即時的檔案：不需要資料副本，也不用選資料夾。

**視窗。** 兩個編輯器同時開著，就像 Visual Studio 的文件視窗：它們是同一個主視窗中的兩個窗格，分頁排在上方：
**關卡 | 事件**。

- **浮動：** 把分頁拖出來，或用 **檢視 → 讓關卡／事件編輯器浮動**。該編輯器會變成獨立的視窗，可以移動、調整大小、
  放到另一個螢幕。它的標題列有 **□**（最大化／還原）和 **⧉**（停駐回去）。
- **停駐：** 把浮動的視窗拖回主視窗上、按兩下它的標題、按 **⧉**，或關閉它。它會再成為分頁，若放在側邊則會和另一個
  編輯器並排（分割）。不是分頁的停駐編輯器會有一條細的標題列和 ⧉，可以拖曳或讓它浮動。
- **檢視 → 兩者都停駐成分頁** 會恢復原狀。

版面（停駐或浮動、大小、位置）會記住，下次開啟時沿用；編輯器移動時開著的東西都不會遺失。**Ctrl+1** / **Ctrl+2**
（**視窗**選單）或 **⇄** 按鈕會把另一個編輯器帶到前面。關閉主視窗時會先詢問未儲存的變更再結束。選單列的 **中文**
切換語言。

**調色盤（原生程式）。**
- **點一下就選取並打開：**點一下怪物、道具、NPC、鑰匙或門，就用它來畫，並打開它的細節視窗（外觀 | 資料）。這個視窗
  不會擋住繪製，會跟著下一次點選切換，位置保持不變；**套用**後仍保持開啟。切換到別的類型前，若有尚未套用的變更會
  詢問（套用 / 捨棄 / 取消）。
- **每個群組都有 +。**怪物、道具與 NPC 會複製一個現有的類型。**門**與**鑰匙**會建立一種新的門和它自己的鑰匙：
  一個 type 為 `story` 的鑰匙道具，以及只有這把鑰匙能開的門（柵門）。新的門出現在「門」，它的鑰匙出現在「鑰匙」。
  地形、樓梯與起點是遊戲內建的（它們的 + 是灰的）。
- **建立之後：**新類型就是目前的筆刷，調色盤會捲到按下 + 的那個群組裡的它，並在**資料**分頁打開它的細節。外觀分頁的
  格子是遊戲的圖片：點一張，就用它來畫這個類型。
- **Id：**小寫字母、中文字、數字與 `_`（不能有空格、大寫、`:` `#` `.` `/` `,`）。
- **你自己的分類：**調色盤最上面的 **+ 新增分類**可以新增一個（任何名稱，中文也可以）。它的標題有 **+**（在裡面建立
  新的怪物、道具、NPC，或門與它的鑰匙）、**✎**（重新命名）與 **✕**（刪除：裡面的類型回到原本的群組，不會刪除任何
  東西）。在類型上按右鍵 → **移到分類**（或回到它原本的群組）。類型屬於哪個分類記在它紀錄裡的 `"group"` 欄位；分類
  清單（順序、空的分類）在 `assets/data/editor_palette.json`。**儲存**會寫入兩者；遊戲不會讀取它們。
- **找不到面板：****檢視 → 關卡面板**列出調色盤、事件、檢查器與檢查；**重設關卡版面**會把它們全部停靠回原本的位置，
  包括漂浮到畫面外的。
- **檢視 → 預設版面**把所有東西放回起始狀態：視窗的大小與位置、兩個編輯器停靠為分頁、兩個編輯器的每個面板停靠在
  起始大小，以及打開的細節視窗放到中間。

**關卡編輯器**的版面和規則與 HTML 版相同（第 2–3 節），放在可以調整大小、可以移動的停駐面板中：

- 物件、事件與屬性；
- 地圖下方的檢查／劇情；
- 相同的工具和按鍵（B R E V O、G、P、[ ]、Ctrl+Z / Y / S、Delete、Esc）；
- ✎ 編輯與類型視窗（2c）；
- 自動放置，相同種子得到相同結果（2b）；
- 儲存時顯示變更清單、備份到 `Build/editor_backups/`、合併事件清單，並更新樓層索引。

地圖由遊戲的渲染器繪製（`GameCanvasView`，和圖集、動畫、粒子編輯器一樣）：

- 精靈圖來自遊戲的圖集；
- 外觀的**動畫會播放**（`anim/<file>.anim#<clip>`），怪物的待機動畫也會；
- 染色會乘上精靈圖的顏色，專屬鑰匙門會蓋上鑰匙的顏色；
- 事件是遊戲的劇情地板。

滑鼠滾輪以游標為中心縮放。右鍵或中鍵拖曳平移（按住空白鍵拖曳也可以）；右鍵點一下不移動是吸管。
沒有 GPU 時，地圖改用 QPainter 繪製（靜態精靈圖）。

**事件編輯器**（第 2 階段）的模型與規則和 HTML 事件編輯器相同（`core/event_project`）：

- **事件樹：** 每個事件池，加上樓層有列但沒有事件池定義的 ID。可搜尋（ID、文字、類型、樓層）、依類型篩選，
  也可以只看有問題的。
- **屬性：** 事件（改名 ID、類型、事件池、可抽到的樓層與 📍、✕、邏輯、六種語言的文字、標題、說明、事件紀錄、
  預覽）、樓層（章節、樓梯與上鎖、從哪裡來、事件），或缺少的 ID（建立它、建立整章，或從樓層移除）。
- **邏輯：**
  - 觸發時機：踩到格子、與 NPC 交談（含對話、完成後對話、樓層與選單順序）、變數改變，或被連結；
  - 可重複，並可設定次數上限；
  - **條件列**（全部 / 任一 / 不是，`{ }` 切換 JSON）、動作列，以及「接著觸發」的連結。
- **下方的分頁：**
  - **問題：** 驗證結果，可依規則篩選、依章節建立，並有修正按鈕。
  - **樓層圖：** 章節是列，樓梯是箭頭，上鎖的樓梯是金色。
  - **變數：** 有分類，可一次處理多個；點一下開啟數值分頁。
  - **類型。**
  - **NPC：** NPC 檔、閒聊台詞與其條件和動作、依選單順序的話題，以及**交談預覽**。
  - **對話：** 節點以卡片呈現，選項有條件、動作與喚醒的事件。
- **歷史記錄：** 每次編輯是一個復原步驟。
- **儲存：** 列出每個檔案的變更、先備份每個檔案，並以 HTML 編輯器的格式寫入（`flags.json`、`counters.json` 保留
  手工對齊的行）。

沒有移植的（屬性面板編輯的是相同的資料）：關係圖、數值圖和邏輯節點圖，HTML 編輯器仍保有這三者。教學也沒有移植，
它使用自己凍結的資料副本。

**兩者合作。** 兩個編輯器直接互相呼叫：

- ⇄ 顯示所選事件的樓層；
- **+ 新增樓層…** 之後按 📍，會以放置模式為該事件開啟關卡編輯器；
- 關卡物件上的 ↗，以及 NPC 的 **在事件編輯器中編輯**，會在事件編輯器中選取它。

一個編輯器儲存後，另一個會重新讀取它自己沒有改過的部分：關卡編輯器讀取事件、NPC 話題和沒動過的樓層；事件編輯器
在沒有未儲存變更時重新讀取全部。每次儲存也都會合併到磁碟上當下的檔案。程式也會監看 `assets/data/events`、
`npcs`、`dialogue` 和 `text.json`，以接收在 HTML 編輯器中做的修改。

| 部分 | 位置 |
|---|---|
| 規則（不含 Qt） | `tools/stage_event_editor/core/`：`stage_project`（檔案、格子、放置、復原、儲存寫入的內容）、`stage_checks`（檢查、劇情的鑰匙／門檢查、安全格、自動放置）、`stage_save`（變更的檔案、差異、備份、樓層索引）、`event_project`（事件編輯器的狀態、驗證、條件列、儲存、交談預覽）。檔案用 nlohmann 的 `ordered_json` 讀寫，所以沒動過的檔案會一個位元組不差地寫回 |
| 視窗 | `tools/stage_event_editor/app/`：`AppShell`（可停駐的主視窗）、`StageEditor`、`StageCanvas`（遊戲渲染器）、`ObjectWindow`、`SpriteBank`、`EventEditor`（+ `EventForms`、`EventTabs`、`EventNpcs`、`EventWidgets`）；字串在 `tools/studio_common/i18n/zh_TW/stage.json` 與 `events.json` |
| 測試 | `unit.stage_core_test` 檢查：每個樓層一個位元組不差地寫回；畫格子、保留字元、物件設定與復原；所有樓層的檢查與劇情檢查；自動放置可重現，且使用 HTML 編輯器的亂數；樓層索引和 `floor_index.json` 一個位元組不差。`stage_editor.app_selftest` 在畫面外測試視窗：畫格子、復原、✎ 編輯、類型視窗、自動放置、表格；事件編輯器的編輯、復原與每個分頁；停駐的分頁 ↔ 浮動 ↔ 分割。`unit.stage_core_test` 中的事件檢查：每個事件池檔已是儲存格式、修改文字／邏輯／旗標時只寫入該檔案（`flags.json` 只改一行）、條件列、交談預覽 |

已用真實資料與 HTML 編輯器比對（無頭 Chrome）：

- 關卡編輯器：`stage_core_test --dump` 在全部 70 個樓層得到相同的檢查數、劇情問題和安全格，自動放置的格子也相同。
- 事件編輯器：`--dump-events` 得到相同的 166 個問題。
- 儲存：做同樣三個編輯（一個動作、一段文字、一個旗標）後，`--dump-write` 寫出的位元組與 HTML 編輯器的儲存相同，
  只有行尾不同。

**為什麼是獨立的程式，而不是 `toms_editor` 的一個分頁。** `toms_editor` 的 Play 分頁會自己啟動 bgfx。工具的
畫布（`GameCanvasView`）則是每個程式共用一個渲染器。獨立的程式讓兩者互不干擾；「從這裡試玩」之後可以做成
這個程式裡的一個遊戲畫布。
