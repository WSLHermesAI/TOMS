# 12 — UI 版面：橫向與直向

**狀態：** 地圖、HUD、通知與戰鬥已完成第 1–3 步（2026-10-25），等待擁有者審閱；其他 10 個畫面接著做（§5）。

## 1. 擁有者的決定（2026-10-25）

| 問題 | 回答 |
|---|---|
| 長螢幕手機（16:9、20:9） | **填滿螢幕，沒有黑邊。** |
| 何時切換方向 | **隨時即時切換**：轉動手機或調整視窗大小立刻切換，戰鬥中也一樣。 |
| 直向的戰鬥畫面 | **怪物在上、玩家在下、操作在最下方**（方便拇指）。 |
| 審閱方式 | **先做戰鬥和 HUD**，兩種方向各截圖，再用同樣方式做其他畫面。 |

## 2. 畫布

所有東西都排在以設計像素為單位的畫布上，再縮放到螢幕（[canvas.h](../../../src/core/engine/canvas.h)）：

- **短邊永遠是 768**，所以兩種方向的文字和按鈕大小相同；
- **長邊跟著螢幕形狀**，從 1024（版面原本設計的 4:3 畫布：4:3 視窗看起來和以前一樣）到 2048；
- 比 4:3 或 3:4 更接近正方形的螢幕，用 4:3 或 3:4 的畫布，會有細細的邊。

| 螢幕 | 畫布 |
|---|---|
| 4:3 視窗、iPad 橫向 | 1024 × 768 |
| 1920 × 1080（16:9） | 1365 × 768 |
| 手機 2400 × 1080 橫向 | 1707 × 768 |
| 手機 1080 × 2400 直向 | 768 × 1707 |
| iPad 直向（3:4） | 768 × 1024 |

`GameSession::fitCanvas` 每幀計算一次。畫布改變時，繪圖器（`BgfxRenderer::kDesignW/H`）、UI（`RmlUi::setDesignSize`：文件重新排版，
並重新比對 `@media` 規則）和遊戲（`Game::canvasChanged`：攝影機立刻配合新畫布）都會跟著改變。

`--design=WxH` 固定一個畫布（加黑邊）；截圖測試固定為 1024 × 768，所以參考圖仍然有效。`--window=WxH` 設定桌面視窗大小
（例如 `--window=540x1200` 可看直向手機的樣子）；`--resize=FRAME:WxH` 在該幀改變視窗大小。2026-10-25 確認：戰鬥以 1280 x 720 開始，
在第 48 幀轉成 540 x 1200，同一場戰鬥就切換成直向版面（反過來也一樣），角色和量條提示也跟著移動。

Android：`screenOrientation="fullSensor"`；Activity 本來就自己處理旋轉（`configChanges`），所以轉動手機就是一次大小改變。

網頁版：頁面上給直向手機的「請把裝置轉為橫向」提示已移除（`src/game/web/shell.html`，2026-10-25）；遊戲改為自行排成直向版面。

`uiScale`（小螢幕上把 UI 物件放大，網頁版在手機上使用）維持原樣，作用在畫布之上。

## 3. 地圖

縮放（`viewCols`，設定）的意思是「1024 寬的畫布上橫跨這麼多格」：在**每一種**畫布上，一格都是 `1024 / viewCols` 設計像素，攝影機顯示放得下
的部分（[camera.h](../../../src/core/game/systems/camera.h) 的 `kZoomWidth`）。寬螢幕顯示更多欄，直向顯示較少欄、較多列，格子大小相同。
視野寬度會算進不完整的格子（預設縮放下，768 寬的畫布放得下 9.75 格），所以能捲到格子地圖真正的邊緣。

## 4. 畫面

每個 `.rcss` 保留橫向規則，再加上 `@media (orientation: portrait)` 區塊（RmlUi 6 支援 `orientation`、`min-height`、`max-width`、
`aspect-ratio` …）。排版規則：

- **橫向**的高度永遠是 768，所以以上方為基準的規則仍然有效；只有寬度變大。原本為 1024 畫布擺放的區塊改成從中央擺放
  （`left: 50%; margin-left: -250px` = 1024 上的 x 262），寬螢幕會讓它保持在中間，而 1024 畫布逐像素不變。
- **直向**寬 768：每一列離兩邊各 40 px（688 px 寬）。要點擊的東西以下方為基準（`bottom: ...`），要閱讀的以上方為基準。
- **遊戲從不複製 UI 的位置。** 遊戲在 UI 元素上繪製的地方（戰鬥中的角色、它們的粒子和傷害數字、攻擊量條的提示），由 `GameUi::sync` 讀取
  元素的版面再告訴遊戲（`Game::setBattleBoxes`、`setComboPointsOnScreen`）。

| 畫面 | 橫向 | 直向 | 狀態 |
|---|---|---|---|
| 戰鬥（`battle.rcss`） | 700 px 的區塊置中 | 角色在上方；敵人計時、攻擊、防禦和必殺以下方為基準。**高的手機**（`min-height: 1300px`）：怪物在玩家上方，各 180 px。**較短的直向**（3:4）：左右並排，134 px | 完成 |
| HUD（`hud.rcss`） | 不變；章節卡置中 | 標題列自動換行、避開選單按鈕；故事列貼在下緣；章節卡橫跨寬度 | 完成 |
| 通知（`overlay.rcss`） | 不變 | 橫跨寬度、放在中間（戰鬥中上方是怪物、下方是操作）；提示訊息較低 | 完成 |
| 玩家選單（`player.rcss`） | 992 × 744 的面板置中；確認對話框在任何畫布上都置中 | 面板填滿螢幕（留 12 px 邊）；每頁的兩欄上下排列（清單在上、細節在下）；狀態頁：屬性數值依內容高度，下面接屬性（較短的 3:4 螢幕：數值在 360 px 內捲動）。清單（格子、事件、系統列）改成 flex 欄位，填滿篩選列下方的高度，也修正了卡片格子超出面板的問題 | 完成（2026-10-25） |
| 對話、商店、選擇關卡、存讀檔、對話框、標題、結局、小遊戲 | — | — | 接下來 |
