### The extendability review in short (19 §8)

- **Easy:** new content (monsters, items, moves, events, NPCs, dialogues, floors, texts) is data only; rules sit in tested pure modules.
- **Medium:** a new kind of event action, play, map thing or condition needs C++ in 2–3 if-chains.
- **Costly:** a new screen: there is no screen state machine; the priority is written in three places.
- Suggested order: a screen state machine, then name → handler tables, then splitting Game by area.
