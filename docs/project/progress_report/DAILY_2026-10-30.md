## Done

| # | Work | Result |
|---|---|---|
| 1 | **Spine import / export: possible?** (question) | Answered: both possible; the bones map directly, Spine's per-vertex deform keys and constraints (IK, transform) are the hard part; an importer of bones only ~1 day, with meshes several days. Not built |
| 2 | **Node effects** ([18](../../engine/18_NODE_EFFECTS.md) §1–4) | A node's `fx` draws it and its whole subtree into a picture of their own (RGBA16F, HDR), then through `fs_layer.sc`: `group`, `motionBlur` (a vector, or the node's own speed), `glow` (HDR + bloom), `flash`, `outline`. Effects nest; `fx` keys animate the params; nothing is drawn into a layer that would show nothing. `IRenderer::beginLayer / endLayer` (a no-op by default), a view and a picture per layer, the view order inner first. **`trail`**: afterimages of a subtree, fading, keyed strength. `.anim` **version 4** (written only when used). Linear filtering for atlases that ask for it (`filter: Linear`) |
| 3 | **The brawler showcase** ([18](../../engine/18_NODE_EFFECTS.md) §5) | ComfyUI (Juggernaut XL + ControlNet union in OpenPose mode, the pose drawn by the script) draws an original brawler once, whole; `tools/art/make_brawler_art.py` cuts it along the same bones into 11 parts (`assets/media/atlas/brawler.*`). `tools/make_brawler_anim.py` writes `brawler.anim` (idle, walk, run, punch, kick, hurt, victory, a KOF-style super combo) and `brawler_sword / _staff / _bow.anim` (five clips each, the weapon at `hand`), the poses solved by two-bone IK |
| 4 | **Elbows and boots fixed** (the owner's screenshot) | Arms (upper + forearm) and legs (trousers + boot) are now one skinned mesh each (the fists their own parts); a toe bone; no arm folds past ~100°. Before: rigid parts showed their cut ends and the boots slid off the cuffs |
| 5 | **The anim editor: effects** | Properties: an **Effect** box (shader, params keyed like the other channels, colour; trail count, gap, colour, blend, strength); the key list's **Fx** and **Trail** columns; Chinese text |
| 6 | **The anim editor: View > Held Clip** | A weapon file's clip of the same name drawn at `hand`, as the game's CharacterRig: the sword, staff and bow attacks can be watched while editing |
| 7 | **`anim_editor --render`** | Frames of a clip through the game renderer, as PNGs (`TOMS_RENDER_ZOOM`) |
| 8 | **The answer: is the anim editor enough without Spine?** ([18](../../engine/18_NODE_EFFECTS.md) §6) | Yes for painted 2D fighters, and beyond it in effects; it lacks IK in the editor, pose tools, draw-order keys, root motion; the showcase's 23 clips were written by a script |
| 9 | **Bone and Lattice modes were slow** (the owner) | The skin overlay (mesh edges, vertex dots) cost 20–28 ms a repaint; now ~2.5 ms (edges drawn once in one call, dots stamped from cached pictures). A viewport repaint 30–40 ms → ~13 ms |
| 10 | **Clip export: File > Export Clips as Animation** ([05](../../engine/05_ANIMATION.md) "Exporting clips") | Check the clips; GIF (one palette for all frames, 1-bit transparency), animated PNG (full colour, soft transparency) or PNG frames; frame rate, scale, background, loop, with the held clip, the folder. Frames drawn by the game renderer offscreen (`BgfxRenderer::setCapture`), framed once per clip. `anim_editor --export` for scripts |
| 11 | **Rendering speed** ([18](../../engine/18_NODE_EFFECTS.md) §4.1) | Runs of quads and meshes of one texture go as one mesh; the renderer joins consecutive meshes; a skin cache per skinned node (no per-frame lookups); automatic weights cached; layer pictures only as big as what they draw; no per-frame allocation for afterimages. 64 idle brawlers: 705 → 129 draw calls; 16 super combos: frame 4.0 → 1.2 ms, GPU 3.9 → 1.2 ms. A benchmark: `toms_game --anim-crowd=N --bench` |
| 12 | **The skin cache shared per clip** | One copy per clip and atlas set, shared by every player of the clip (~43 KB a brawler: 2.7 MB less for 64, 43 MB for 1000); no speed change (measured back to back) |
| 13 | **Crowd answers** | 100 brawlers fit a 60 fps frame on this PC (idle 5.9 ms, walk 3.8, super combo 4.1) except `run` (15.3 ms: its afterimages take the slow path; 48 of 100 blur layers drawn). 1000 run at 20–30 fps. The ways to more are written down as options (§4.1) |

  new art (another view, another character) needs `make_brawler_art.py` run again and its joints measured.
- **`.anim` version 4** files (any with `fx` or `trail`) do not open in builds older than today's.
- **Layers are only checked on Windows (D3D11).** They need render targets; the web and Android are not checked.
